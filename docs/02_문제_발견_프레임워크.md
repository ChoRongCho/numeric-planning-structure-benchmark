# 문제 발견 프레임워크

## 목적

이 문서는 “어느 planner가 못 풀었다”를 “numeric planning의 어떤 구조적 한계가
드러났다”로 바꾸기 위한 분석 절차다. 논문 문제는 solution 아이디어가 아니라
반복 가능하고 원인을 분리할 수 있는 failure mechanism으로 정의한다.

## 1. 먼저 실패 단계를 분리한다

| 단계 | 관찰 예시 | 이것만으로 말할 수 있는 것 | 아직 말할 수 없는 것 |
|---|---|---|---|
| 입력/지원 | parse error, unsupported | planner와 PDDL fragment 불일치 | heuristic 한계 |
| grounding/번역 | action 수 폭발, 번역 timeout | representation 또는 grounding 병목 | search guidance 실패 |
| heuristic 계산 | 한 번의 평가가 매우 비쌈 | heuristic computation bottleneck | 정보 손실에 의한 오도 |
| state ranking | 서로 다른 cost-to-go가 같은 `h` | 구분력 부족 후보 | 전체 runtime 원인 확정 |
| search control | helpful action 밖에 정답 action 존재 | pruning/preferred-action 문제 후보 | core heuristic만의 문제 |
| feasibility | LP/SMT check 지배, 많은 infeasible partial plan | constraint 검사/encoding 병목 | delete relaxation만의 문제 |
| plan 출력 | invalid, extraction 실패 | 구현 또는 adapter 문제 | planning failure |

분석 보고서에는 반드시 가장 이른 실패 단계를 기록한다. `timeout`은 원인이 아니라
최종 증상이다.

## 2. 정보 손실 후보를 명시한다

Relaxation 전후를 비교할 때 “숫자를 무시한다”처럼 넓게 말하지 않는다. 실제로
사라지거나 약해진 정보 단위를 적는다.

### Boolean 구조

- delete effect와 사실 재달성 비용
- mutex와 동시에 참일 수 없는 선택
- action ordering과 irreversible choice
- 동일 목표를 위한 supporter 간 간섭

### Numeric 구조

- 소비된 자원의 누적과 resource upper/lower bound
- action repetition 횟수와 정수성
- assignment가 이전 증가량을 덮어쓰는 효과
- 여러 조건이 같은 fluent를 공유할 때의 competition
- 실제로는 함께 선택할 수 없는 producer/consumer 조합

### Numeric-symbolic coupling

- 어떤 객체가 어떤 weight/capacity를 갖는지에 대한 identity
- aggregate 총량은 같지만 packing 가능성이 다른 grouping
- 같은 numeric value에서 symbolic location/ownership이 만드는 차이
- 하나의 symbolic 선택이 여러 numeric constraint에 미치는 연쇄 효과

각 실험은 위 후보 중 하나를 주요 독립 변수로 선택하고 나머지는 가능한 한
고정한다.

## 3. 문제 family를 만든다

한두 개 IPC instance의 timeout만으로 구조를 주장하지 않는다. 최소 문제에서 시작해
다음 축을 독립적으로 변화시키는 parametric family를 만든다.

| 축 | 예시 조작 | 통제해야 할 것 |
|---|---|---|
| 크기 | object/action/goal 수 | tightness와 coupling |
| tightness | capacity 대비 요구량, slack | object 수와 topology |
| coupling | 공유 resource/goal 수 | 총 resource 양과 plan 길이 |
| grouping | 같은 총 weight의 item 분할 | capacity, 거리, goal 수 |
| topology | 선택 경로와 bottleneck 수 | numeric demand |
| dead-end density | 되돌릴 수 없는 선택 수 | branching factor |

최소 반례, 구조가 제거된 대조군, 구조가 강화된 확장군을 한 세트로 둔다.

## 4. 결과보다 중간 메커니즘을 측정한다

### 최종 지표

- coverage, timeout, runtime, plan cost/length

### 원인에 가까운 지표

- grounding time과 ground action 수
- heuristic evaluation 시간과 호출 횟수
- initial-state heuristic 값
- sampled state의 true distance 대비 heuristic error
- pairwise state-ranking accuracy와 ranking reversal
- heuristic plateau 크기와 길이, distinct `h` 값 수
- expanded/generated/duplicate/reopened state 수
- helpful/preferred action recall
- infeasible successor 또는 LP/SMT rejection 수

논문 주장은 가능한 한 원인에 가까운 지표에서 먼저 성립하고 최종 지표로 이어져야
한다.

## 5. 비교군으로 설명을 제거한다

| 비교 | 제거하려는 대안 설명 |
|---|---|
| 동일 planner + blind | heuristic이 실제로 도움이 되는지 |
| 동일 planner + 여러 heuristic | search engine/implementation 차이 |
| 동일 heuristic + search 정책 변경 | heuristic과 helpful-action pruning 혼동 |
| heuristic search vs SMT/OMT | state ranking 문제와 bounded encoding 문제 |
| grounded vs 가능한 lifted/compiled 표현 | grounding 병목 |
| 원본 vs 구조 제거 대조군 | 단순 instance 크기 효과 |
| oracle 또는 정보 한 조각 복원 | 지목한 누락 정보의 인과성 |

모든 13개 planner가 동일한 실험 질문에 필요한 것은 아니다. 방법론을 대표하면서
대안 설명을 제거할 수 있는 최소 비교군을 선택한다.

## 6. 반증 조건을 먼저 쓴다

현재 coupling/tightness 가설은 다음 중 하나가 관찰되면 수정하거나 폐기한다.

- 크기를 통제하면 coupling/tightness 효과가 사라진다.
- heuristic ranking은 유지되는데 runtime만 악화된다.
- blind 또는 비-relaxation planner도 동일한 비율로 악화된다.
- 지목한 정보를 복원해도 plateau와 expansion이 줄지 않는다.
- 현상이 특정 parser, domain encoding 또는 binary에서만 나타난다.
- seed나 tie-breaking 변화가 구조 변수보다 효과가 크다.

승격한다.


## 현재 우선 작업

1. 완료된 10-planner 결과에서 domain/problem별 최초 실패 단계를 다시 분류한다.
2. solved/timeout 집계가 아니라 heuristic 계열별로 실패가 집중된 문제 구조를 찾는다.
3. capacity/grouping 최소 문제 family에서 size, tightness, coupling을 독립 조절한다.
4. heuristic 값과 expansion trace를 얻을 수 있는 planner부터 내부 계측한다.
5. 관찰된 패턴이 [01 연구 문제 정의](01_연구_문제_정의.md)의 승격 기준을
   만족하는지 판단한다.
