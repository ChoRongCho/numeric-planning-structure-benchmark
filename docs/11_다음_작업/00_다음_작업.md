- `unsupported`: 언어/기능 미지원

## 7. 실패 위치를 단계별로 분석

Planner 실패를 하나의 timeout으로만 기록하지 않는다.

```text
PDDL parsing
  → grounding
  → heuristic initialization
  → initial state estimate
  → search plateau/dead end
  → first plan
  → metric 개선
  → VAL validation
```

- [ ] grounding에서 폭발했는지 확인

- [ ] relaxed plan이 생략한 refill/charge/clean/tool-change 행동 수 계산
- [ ] solution quality 악화와 plan 발견 실패를 분리
- [ ] 동일 현상이 여러 planner/heuristic에서 반복되는지 확인

## 9. 구조적 한계 판정 기준

다음 증거가 함께 있을 때만 relaxation의 구조적 한계라고 주장한다.

1. 객체 수와 graph를 고정해도 numeric tightness에 따라 성능이 악화된다.
2. Relaxed plan에서 실제 필요한 보충·세척·교체 행동이 사라진다.
3. Initial heuristic 오차 또는 state ranking 오류가 함께 증가한다.
4. 단순 grounding 크기만으로 성능 변화를 설명할 수 없다.
5. 둘 이상의 planner/heuristic에서 유사한 경향이 재현된다.
6. 대조군이나 반증 조건에서는 현상이 약해진다.

이 기준을 만족하기 전에는 새로운 learned guidance나 heuristic 구현으로 넘어가지
않는다.
