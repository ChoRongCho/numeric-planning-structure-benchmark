# p000 최소 인스턴스 검증

## 목적

각 domain에 빈 plan으로는 풀 수 없지만 핵심 행동 몇 개면 끝나는 `p000`을
추가했다. `p000` 실패는 큰 탐색 공간 때문이라고 설명할 수 없으므로 parser,
numeric 표현 지원, relaxation 또는 planner 구현 한계를 찾는 기준선으로 쓴다.

| Domain | 최소 의도 |
| --- | --- |
| 01 Blocksworld | 블록 하나를 한 번 집기 |
| 02 Logistics | 이미 적재된 소포를 1-edge 운송 후 하차 |
| 03 Books | 같은 방의 책 하나를 지정 shelf slot에 배치 |
| 04 Watering | 보유한 물 1단위로 식물 하나를 급수하고 용기를 내려놓기 |
| 05 Barman | shot 하나에 ingredient를 채우고 테이블에 놓기 |
| 06 Assembly | part 하나를 배치·체결·검사하고 tool 원상복구 |

모든 파일은 기존 domain과 같은 metric을 최소화한다. 전체 catalog는 45 domain,
556 problem이며 VAL parser 검사 결과는 556/556 clean이다.

## 13개 planner 결과

maintained `optic`과 local `optic-cplex`를 모두 포함했다. 두 planner 모두
`-N`에서 p000 6/6 valid였고, maintained `optic -N`은 p001도 6/6을 풀었다.
`-N`은 metric 최적화를 무시하므로 이 결과는 호환성 확인으로만 해석한다.

- 6/6 valid: ENHSP, Metric-FF Cross v1, Count Downward Agile, PlanForge,
  Panino, TamerLite, Tempest, Numeric Fast Downward, OPTIC, OPTIC-Cplex
- OPTIC과 OPTIC-Cplex: `-N` smoke에서 각각 6/6 valid.
- Patty는 Books, Watering, Barman, Assembly 4개가 valid다. Pattint는 Books,
  Barman, Assembly 3개가 valid이고 Watering에서는 반복 `charge-battery`를 넣은
  invalid plan을 출력했다. 두 planner 모두 Blocksworld와 Logistics에서 기존
  `:action-costs`/typing parser 문제로 실행 전 실패했다.
- POPF static v2: Blocksworld, Logistics, Books는 valid. Watering은 timeout,
  Barman과 Assembly는 unsolvable로 판정했다.

따라서 `p000` 자체는 6개 모두 여러 독립 planner에서 valid plan을 얻었다.
남은 실패는 인스턴스 규모가 아니라 planner별 표현 및 탐색 한계로 분류한다.
