# 연구 기록

## 2026-09-11

### 관찰

- 첫 10개 planner로 전체 domain의 `p001`을 실행했다.
- planner마다 search, heuristic, SMT/LP machinery가 달라 timeout만으로 공통 원인을
  말할 수 없음을 확인했다.
- 10개 중 PATTY/PATTINT는 state-ranking heuristic search가 아니며, 나머지도
  `hadd`, `hFF`, interval relaxation, numeric LM-cut으로 나뉜다.

### 결정

- 프로젝트의 목적을 solution 개발이 아니라 numeric planning의 구조적 문제 발견과
  원인 검증으로 다시 명시했다.
- 실패를 입력, grounding, heuristic 계산, state ranking, search control,
  feasibility, plan output 단계로 분리한다.
- 문서를 연구 문제에서 시작하는 논문 순서로 재배치하고 한글 번호 파일명으로 통일했다.
- 일반 numeric planning을 지원하지 않는 Powerlifted는 비교군에서 제거했다.
- 로컬 `OPTIC-CPLEX`, `POPF Release 2`, modified Numeric Fast Downward를 공통
  실행기에 추가했다.

### 다음 작업

- 완료된 결과를 domain/problem별 최초 실패 단계로 다시 분류한다.
- 단순 solved/timeout이 아니라 heuristic 계열별 공통 failure structure를 찾는다.
- capacity/grouping 문제에서 size, tightness, coupling을 독립적으로 바꾸는 최소
  instance family를 만든다.
- heuristic value, ranking, plateau와 expansion을 얻기 위한 계측 가능성을 확인한다.

## 2026-09-07

### Current understanding

- 기존 numeric planner는 numeric precondition/effect와 여러 numeric-aware
  heuristic을 이미 처리한다.
- 따라서 "planner가 숫자를 이해하지 못한다"는 전제는 연구 질문으로 부족하다.
- 우선 relaxation이 combinatorial resource interaction을 실제로 잃는지
  controlled benchmark로 확인해야 한다.

### Decision

프로젝트의 중심을 LLM 적용이 아니라 planning heuristic failure의 검증에 둔다.

### Next

- baseline planner/heuristic 후보를 확정한다.
- 12kg carrier와 item grouping을 이용한 최소 반례 family를 설계한다.
- size, tightness, coupling을 각각 조절할 수 있는지 확인한다.
