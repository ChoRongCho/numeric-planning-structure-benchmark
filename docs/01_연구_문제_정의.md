# 연구 문제 정의

## 연구의 출발점

Numeric planner가 어떤 문제에서 실패하거나 느려진다는 사실만으로는 논문 문제가
되지 않는다. parser 미지원, grounding 폭발, heuristic의 정보 손실, search 정책,
numeric feasibility 검사 비용, 구현 버그는 모두 같은 timeout으로 보일 수 있다.

이 연구의 목적은 기존 numeric planner의 성능 순위를 만드는 것이 아니라 다음
인과 사슬에서 **어느 정보가 어디에서 사라지고, 그것이 언제 실제 탐색 실패로
이어지는지 찾는 것**이다.

```text
원래 문제의 구조
  → heuristic 계산을 위한 relaxation/abstraction
  → 보존되거나 삭제된 정보
  → state/action의 잘못된 가치 추정
  → plateau·잘못된 분기·과도한 node expansion
  → timeout 또는 coverage 저하
```

## 연구 대상: deterministic numeric robot task planning

`Robotics domain`은 별도의 PDDL 문법 범주가 아니다. 일반 planning 문제 중 action이
로봇의 실행 가능한 skill에 대응하고, 물체와 로봇의 물리적 자원이 planning state에
연결되는 응용 부분집합으로 본다.

일반 numeric planning이 연료, 비용, 수량, 용량을 추상적인 scalar resource로 다룰
수 있다면, robot task planning에서는 그 값이 다음 symbolic 정보와 강하게 결합된다.

- 어떤 robot/arm/hand가 action을 수행하는가
- 어떤 물체가 어떤 weight, volume, location, ownership을 갖는가
- 어떤 gripper, tool, fixture, container, device 또는 workspace를 점유하는가
- 어떤 준비, tool change, refill, cleaning, temporary placement가 필요한가
- 앞선 symbolic choice가 이후의 numeric feasibility를 어떻게 바꾸는가

따라서 이 연구에서 일반 numeric domain과 robotics domain을 가르는 핵심은 숫자의
존재가 아니라 **embodiment와 실행 가능성에 연결된 numeric-symbolic coupling**이다.
동일한 총량을 가진 상태라도 물체 identity, grouping, 점유 관계와 action ordering이
다르면 로봇이 실제로 실행할 수 있는 plan은 달라질 수 있다.

## 현재의 중심 연구 질문

> Deterministic robot task planning에서 물체 identity와 제한된 embodied resource가
> symbolic action choice와 결합될 때, numeric relaxation은 어떤 interaction 정보를
> 손실하며, 그 손실은 heuristic의 state-ranking과 search 성능을 어떻게
> 악화시키는가?

이 질문은 아직 결론이 아니라 검증할 대상이다.

## 세부 연구 질문

### RQ1. 무엇이 삭제되거나 합쳐지는가?

- Boolean delete relaxation이 mutex, 선행조건 재달성, 순서 의존성을 얼마나 잃는가?
- Numeric relaxation이 자원 소비, 상한, 반복 횟수, assignment와 같은 정보를
  어떤 방식으로 근사하는가?
- 개별 객체의 identity, grouping, shared resource competition이 aggregate numeric
  값으로 합쳐지는가?
- 손, gripper, tool, fixture, container와 workspace의 점유·배타성이 relaxed state에서
  얼마나 약해지는가?
- tool change, refill, cleaning, regrasp와 temporary placement처럼 goal을 직접
  달성하지 않는 준비·복구 action의 비용이 얼마나 과소평가되는가?
- 각 planner의 `hadd`, `hFF`, interval relaxation, numeric LM-cut, abstraction은
  서로 무엇을 보존하는가?

### RQ2. 언제 어려워지는가?

- 문제 크기 자체와 무관하게 resource tightness가 증가할 때 어려워지는가?
- symbolic choice와 numeric constraint의 coupling이 증가할 때 어려워지는가?
- goal 간 자원 공유, packing/grouping, 반복 action, dead-end 구조가 영향을 주는가?
- 조립 순서, 도구 선택, 용기 선택, 임시 배치와 같은 symbolic choice가 이후 numeric
  feasibility를 바꾸는 정도가 클수록 어려워지는가?
- 같은 문제에서도 heuristic은 실패하지만 SMT/OMT 계열은 버티는 구간이 있는가?

### RQ3. 관찰된 실패가 정말 relaxation 때문인가?

- grounding 시간과 search 시간을 분리했을 때도 현상이 남는가?
- blind heuristic, 서로 다른 relaxation, symbolic planner와 비교해 원인을 분리할
  수 있는가?
- heuristic error/ranking reversal이 expansion과 runtime보다 먼저 나타나는가?
- 정보 하나만 복원한 작은 oracle 또는 handcrafted heuristic이 현상을 제거하는가?

## 현재 작업 가설

Aggregate numeric information은 전체 자원량은 표현하지만, robot task의 물체
identity, shared embodied resource, 점유 관계와 준비·복구 action이 만드는 객체별
grouping/packing interaction을 충분히 구분하지 못할 수 있다. 이 정보 손실은
resource가 빡빡하고 symbolic choice와 numeric feasibility의 coupling이 강할수록
커지며, 비슷한 heuristic 값을 가진 상태가 늘어나 plateau와 불필요한 확장을 만들
가능성이 있다.

이 가설은 [02 문제 발견 프레임워크](02_문제_발견_프레임워크.md)의 반증 기준을
통과해야 한다.

## 필요한 증거

- 크기와 분리해 조절한 tightness/coupling의 효과
- 실제 cost-to-go 대비 heuristic error 또는 state-ranking accuracy
- plateau 길이, heuristic distinct value 수, node expansion과 duplicate 수
- helpful/preferred action이 정답 경로를 배제하거나 지연시키는 빈도
- planner별 solved/timeout뿐 아니라 실패한 내부 단계
- 동일 구조의 최소 반례와 구조를 제거한 대조군
- 최소 두 개 이상의 서로 다른 구현에서 반복되는 경향
- 생성된 high-level action이 실제 robot skill sequence로 대응될 수 있다는 실행 의미

## 구조적 문제로 인정하는 기준

다음 조건을 모두 만족해야 논문의 중심 문제 후보로 승격한다.

1. 동일한 현상이 재실행에서 반복된다.
2. PDDL 미지원, crash, validator 오류, 단순 grounding 병목으로 설명되지 않는다.
3. 문제 크기를 통제해도 특정 구조 변수에 따라 악화된다.
4. heuristic 값이나 state ordering에서 원인과 가까운 중간 증거가 관찰된다.
5. 해당 구조를 제거하거나 누락 정보를 복원하면 현상이 약해진다.
6. 하나의 binary에만 있는 구현 버그가 아니라 방법론과 연결된다.

## 1차 연구 범위

### 포함

- deterministic, fully observable robot task planning
- sequential numeric PDDL
- predicate와 numeric fluent가 함께 있는 state
- 실제 robot skill로 대응 가능한 discrete action
- 물체 identity와 weight/volume/amount/location의 결합
- hand, gripper, tool, fixture, container, device, workspace의 제한과 점유
- consumable/replenishable resource와 capacity constraint
- preparation, transfer, cleaning, tool change, refill, temporary placement

### 1차 범위에서 제외

- continuous motion planning과 collision checking
- trajectory optimization, dynamics와 force control
- perception/state-estimation uncertainty
- stochastic action outcome과 execution failure recovery
- multi-robot coordination
- temporal concurrency와 continuous effect를 중심으로 한 주장

Temporal planner인 OPTIC과 POPF는 비교 축으로 사용할 수 있지만, 중심 주장은 먼저
sequential numeric robot task planning에서 세운다. 즉, high-level plan이 robot
skill sequence로 옮겨질 수 있어야 하지만 arm trajectory 자체를 현재 planner가
계산하도록 요구하지 않는다.

## 검증할 domain 구조 후보

아래 항목은 benchmark 설계가 확정됐다는 뜻이 아니다. 어떤 구조를 독립 변수로
분리할 수 있는지 검토하기 위한 후보군이다.

| 구조 family | 후보 domain | 관찰하려는 coupling |
|---|---|---|
| 자원 전달·분배 | watering, barman, laboratory | 수량, 용기, refill, cleaning, 장비 점유 |
| 도구·점유·선행관계 | assembly | tool/fixture 선택, 조립 순서, 준비·복구 action |
| 운반·재배치·용량 | books, logistics | payload, shelf/container capacity, 임시 배치 |
| 순수 symbolic 대조군 | blocksworld | numeric coupling이 없는 기본 delete-relaxation 효과 |

각 후보는 [02 문제 발견 프레임워크](02_문제_발견_프레임워크.md)에 따라 최소 반례,
구조 제거 대조군, 구조 강화군을 함께 설계해야 한다. 기존 domain 이름을 선택했다는
이유만으로 benchmark에 포함하지 않는다.

## 후속 단계와 경계

실제 로봇 실행은 발견된 문제 구조가 현실의 skill execution에도 의미가 있는지
확인하는 후속 validation이다. 실제 실행을 먼저 만들고 그 성공 여부를 heuristic
한계의 증거로 사용하지 않는다. SLM/LLM 역시 현재 연구 질문이 아니며, 기존
heuristic의 failure가 재현되고 잃어버린 정보가 확인된 뒤 이를 복구하는 여러 방법
중 하나로만 검토한다.
