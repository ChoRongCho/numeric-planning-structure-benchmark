# 수치 플래닝 자료 실행 상태 행렬

기준일은 2026-09-07이다. 확보한 **121개 artifact**와 실험에서 선택하는
**planner 구성 ID**는 서로 다른 단위다. 압축본, 동일 플래너의 여러 release,
solver backend, library, benchmark dataset은 PDDL plan을 생성하는 프로그램이
아니다.

## 현재 실험 가능 범위

| 판정 | 수 | 실험 처리 |
|---|---:|---|
| batch 실행 가능 | 43 구성 | YAML `planners`와 `"*"`에서 사용; 이 중 `popf-static-v2`는 사용자 host 확인 |
| build 완료, 장시간/반복 회귀 검증 미통과 | 7 구성 | 명시적으로 batch 제외 |
| numeric compiler 검증 | 1 | `plannerctl` 직접 실행 |
| CLI/JVM 시작 검증 | 4 | PDDL batch 제외 |
| 현 host/legacy runtime 차단 | 11 | 보존 VM/container 필요 |

43개 ID의 정확한 목록과 현재 상태는 아래 명령으로 생성한다. 문서에 복사한
목록보다 이 출력이 우선한다.

```bash
cd scripts/run
./benchmarkctl planners
```

## Archive/binary 64개의 처리 원칙

64개 전부의 이름과 SHA-256은
[07 확보 자료 보고서](07_확보_자료_보고서.md)의 두 번째 표에
명시돼 있다. 이들은 다음 네 종류다.

- 현재 runtime에 실제 투입된 배포본: Metric-FF, LPG-td, CRIKEY2,
  TamerLite, NextFLAP, FAPE, SAPA, Aries Linux, static `optic-cplex`.
- 별도 제공 artifact: `planners/local/numeric-fast-downward`의 modified source/build는
  `numeric-fast-downward-local`로 VAL 검증했다. POPF Release 2 static binary는
  사용자 Ubuntu host에서 실행이 확인되어 `popf-static-v2` batch ID로 등록했다.
  Codex sandbox의 32-bit seccomp에서는 실행할 수 없으며, 실제 batch에서 생성되는
  plan은 공통 runner가 VAL로 검사한다.
- 역사적 planner release/IPC snapshot: POPF, OPTIC, COLIN, LPRPG, HSP*,
  CPT, TSGP, SGPlan6, MIPS-XXL, GAMER, TFD 등. 원본은 보존하되 현대 host에서
  검증된 구성만 batch에 올린다.
- 비실행 자료: IPC corpus와 temporal domain archive.
- 현재 host용이 아닌 중복 binary/dependency: Windows/macOS/Sparc/32-bit
  실행 파일, flex++/bison++ source, wheel과 sdist의 중복 배포본.

따라서 64개를 각각 planner ID로 만드는 것은 중복 실험과 잘못된 실행을
만든다. 대신 SHA-256 검증은 `scripts/verify_numeric_downloads.sh`, 실행 검증은
`runtime-status.tsv`와 `smoke-*.log`로 독립 관리한다.

## batch 제외가 중요한 사례

- `numeric-fast-downward`, `lnm-plan-ipc2023`: native build와 CLI 및 단발
  VAL 성공 사례는 있지만 동일 입력 반복 실행에서 invalid 0-step plan도
  관측돼 wildcard에서 제외했다.
- `count-downward-opt-domain-abstractions`,
  `count-downward-together-opt-2`: tiny smoke에서도 120초 안에 plan이 없었다.
- `bitblast`: solver가 아니라 numeric-to-classical compiler다.
- Aries/FAPE/SAPA: protobuf service, ANML 또는 legacy CLI라 현재 PDDL batch
  계약과 다르다.

이 항목들은 삭제하지 않는다. 상태를 보존하면서 YAML wildcard에서만 제외해
실험 결과의 무결성을 지킨다.
