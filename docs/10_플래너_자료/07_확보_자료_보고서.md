## 3. 실행 가능성은 다운로드 수와 별도다

121개가 모두 planner executable인 것은 아니다. 이 집합에는 planner의 여러 버전, solver backend, adapter/library, benchmark, Windows/macOS binary가 포함된다. 한 source가 여러 공식 탐색 구성을 제공하므로 artifact 수와 YAML planner ID 수도 일치하지 않는다.

| 상태 | 수 | 항목 |
|---|---:|---|
| batch 실행 가능 | 43 구성 | `scripts/run/benchmarkctl planners`에서 `batch=true`인 ID; `popf-static-v2`는 사용자 host 실행 확인 후 plan별 VAL 검사 |
| compiler 변환 성공 확인 | 1 | BitBlast |
| CLI/JVM 시작 확인 | 4 | Aries, FAPE 1.0.4, FAPE 1.0, SAPA |
| build됐지만 batch 검증 보류/실패 | 7 구성 | Count Downward optimal 2개, Numeric Fast Downward, LNM-Plan 공식 4개 |
| 32-bit binary가 현재 sandbox seccomp에서 차단 | 3 | CPT, CRIKEY3.1 static, TSGP static |
| 독립 source/runtime staging 후 legacy build/runtime 차단 | 8 | MIPS-XXL 2종, GAMER, HSP*P, SGPlan6 3종, TFD IPC 2008 |

실행기·solver가 아닌 Git backend/library/dataset은 표의 독립 디렉터리 자체가 재현 단위다. 빌드 가능한 source라고 해서 현재 host에서 이미 실행 검증됐다는 뜻은 아니다.

## 4. 공통 실행 인터페이스

```bash
planners/plannerctl list
planners/plannerctl status metric-ff
planners/plannerctl run metric-ff -o DOMAIN -f PROBLEM
planners/plannerctl run enhsp -o DOMAIN -f PROBLEM
planners/plannerctl run tamerlite DOMAIN PROBLEM
planners/plannerctl run nextflap DOMAIN PROBLEM
```

각 runtime은 `planners/runtime/<id>`에 분리되어 있다. Python planner는 서로 다른 `site-packages`를 사용하며 시스템 Python에 설치하지 않았다. Java/native 배포본도 각 runtime 안의 파일만 참조한다.

모든 검증 명령과 차단 원인은 [03 실행 안내](03_실행_안내.md)에 있다.
