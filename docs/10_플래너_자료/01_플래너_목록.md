# 수치 플래너와 솔버 목록

## 표기

- **A — 공개·현행:** 공식/저자 repository가 있고 비교적 현대적인 설치 경로가 있음
- **B — 공개·legacy:** source/archive는 있으나 오래된 compiler/dependency patch 가능성이 큼
- **C — artifact/prototype:** 논문 artifact 또는 IPC frozen source는 있으나 연구 prototype 성격
- **D — 논문 중심:** 논문은 확인했지만 안정적인 공개 구현을 이번 조사에서 확인하지 못함

`Sequential`, `Temporal`, `PDDL+`는 서로 대체 관계가 아니다. 예를 들어 ENHSP는
sequential numeric과 PDDL+ 일부를 지원하지만 durative action 자체는 지원하지 않는다.

## 1. 현대 sequential numeric planner

### 1.1 ENHSP / JPDDL+ — A

- 방식: forward heuristic state-space search
- 범위: classical, linear/nonlinear numeric, discretised process/event, global constraint
- 탐색: GBFS, A* 등; satisficing/일부 fragment optimal
- 핵심 heuristic: interval/subgoaling `hadd`, `hmax`, multi-repetition relaxed plan,
  landmarks, helpful/up-to-jumping action, AIBR/effect abstraction 계열
- 주의: durative action은 직접 지원하지 않고 compile-out해야 하며, heuristic마다
  지원하는 논리식 범위가 다르다.
- 코드: [hstairs/enhsp](https://github.com/hstairs/enhsp)
- UP adapter: [aiplan4eu/up-enhsp](https://github.com/aiplan4eu/up-enhsp)
- 판단: 가장 넓은 표현력의 1차 실행 substrate. 연구 baseline에서 필수.

### 1.2 Numeric Fast Downward(NFD) / NLM-CutPlan — C

- 방식: Fast Downward 기반 progression search
- 범위: SNP/LNP 중심, cost-optimal과 satisficing
- 핵심: numeric LM-cut family, numeric `hmax`, operator-counting LP/IP,
  numeric landmarks, numeric bounds, state equations, symmetry/orbit-space search,
  Gurobi 기반 IP compilation
- 2023 Numeric IPC에서는 NLM-CutPlan 계열이 모든 subtrack을 석권했다.
- dependency: 오래된 Python 2.7 translator, CPLEX; 일부 기능은 Gurobi/Bliss 필요
- 코드: [Kurorororo/numeric-fast-downward](https://github.com/Kurorororo/numeric-fast-downward)
- 판단: optimal numeric heuristic 연구의 de facto reference codebase지만 빌드 격리가 필요.

### 1.3 PATTY — A/C

- 방식: Symbolic Pattern Planning(SPP), pattern을 SMT formula로 encoding
- 범위: linear numeric; 이후 temporal numeric과 ICE까지 확장
- 특징: action pattern이 causal order를 제안하고 SMT가 반복 횟수와 feasibility를 결정
- 구성: static pattern, dynamic pattern, brave/greedy search, cost-effective plan cleanup
- 코드: [matteocarde/patty](https://github.com/matteocarde/patty),
  [IPC 2026 frozen source](https://github.com/ipc2026-numeric/team-2)
- 판단: highly numeric/짧은 horizon에서 search planner와 상보적인 필수 symbolic baseline.

### 1.4 OMTPlan — A

- 방식: bounded planning을 SMT/OMT로 환원
- 범위: PDDL2.1 level 2; satisficing과 optimal; unit/constant/state-dependent action cost
- backend: Z3/νZ, SMT-LIB export 가능
- 구성: serial/parallel encoding, linear/exponential horizon 증가
- 코드: [fraleo/OMTPlan](https://github.com/fraleo/OMTPlan)
- 판단: rich cost structure와 optimal symbolic planning 비교에 필수.

### 1.5 RanTanPlan / R2∃ 계열 — B/C

- 방식: planning as SMT
- encoding: linear semantics, exists-step, semantic interference,
  relaxed-relaxed-exists-step와 informed ordering
- backend: Yices, Z3
- 코드: [JoanEspasa/rantanplan-public](https://github.com/JoanEspasa/rantanplan-public)
- 판단: PATTY 이전 SMT encoding의 역사적·실험적 비교군.

### 1.6 SpringRoll — C/D

- 방식: sequential numeric planning을 SMT로 encoding
- 특징: 같은 action의 임의의 유한 반복을 한 plan step에 roll-up;
  disjunctive global constraint 지원
- 구현: SPRINGROLL prototype
- 공식 저자 자료: [Enrico Scala tools](https://sites.google.com/view/enricoscalashomepage/tools-software-and-experiments)
- 판단: action repetition과 긴 plan horizon을 연구할 때 중요한 symbolic baseline.

### 1.7 BitBlast — A

- 방식: bounded SNP numeric variable을 Boolean encoding으로 변환해 classical planner 사용
- encoding: one-hot, binary BLAST, axiom 기반 BLAST-X
- backend: Unified Planning + LAMA 등 classical planner
- 코드: [LBonassi95/BitBlast](https://github.com/LBonassi95/BitBlast)
- 판단: native numeric solver가 정말 필요한지 검증하는 compilation baseline.

### 1.8 Conditional-effect numeric compiler — A/C

- 방식: numeric conditional effect를 SNP/LNP 또는 지원 fragment로 compilation
- 코드: [Plutone/numce-compiler](https://github.com/Plutone/numce-compiler)
- 판단: planner 간 PDDL feature mismatch를 줄이는 전처리 후보.

## 2. IPC 2026 최신 numeric planner

공식 명단·결과·frozen source 링크는
[IPC 2026 Numeric Tracks](https://ipc2026-numeric.github.io/)를 기준으로 한다.

### 2.1 Panino — C

- 전체 satisficing 및 agile winner
- 방식: JPDDL+ 위의 GBFS
- heuristic: subgoaling `hadd` partition 안에서 propositional achievement와 numeric
  distance feature의 novelty를 계산; conjunction width 1–2
- anytime 구성은 cost-bound restart로 solution quality 개선
- source: [IPC team-3](https://github.com/ipc2026-numeric/team-3)
- 판단: 현재 satisficing/agile 최우선 비교군.

### 2.2 TamerLite — A

- 방식: UP frontend + Python/Rust forward heuristic search
- 범위: SNP/LNP, durative action, duration inequality, ICE
- search: A*, weighted A*, GBFS, BFS, EHC, multi-queue
- heuristic: `hFF`, numeric `hadd`, `hmax`, custom Python heuristic
- code: [fbk-pso/tamerlite](https://github.com/fbk-pso/tamerlite),
  [IPC team-4](https://github.com/ipc2026-numeric/team-4)
- 판단: 새 heuristic을 끼우기 가장 좋은 현대 prototype substrate 후보.

### 2.3 Tyr — C

- 전체 optimal winner
- 방식: C++ library + Python binding; ground 및 lifted numeric planning
- 범위: SNP/LNP, negative/disjunctive/quantified conditions, conditional effects,
  derived predicates, action costs
- optimal: eager A* + blind; agile/satisficing: lazy GBFS + goal count 또는 lifted additive RPG
- lifted successor generation: substitution-consistency graph, Datalog, final exact check
- source: [IPC team-5](https://github.com/ipc2026-numeric/team-5)
- 판단: grounding explosion과 lifted numeric search를 연구할 때 필수.

### 2.4 nplanning — C

- 방식: self-contained C++17 forward state-space search; ppmajal Java bridge
- 범위: LNP; exact successor + approximate heuristic
- 핵심: numeric delete relaxation, chained-numeric relaxed plan, width novelty,
  sound numeric state-dominance pruning, monotonicity 분석
- source: [IPC team-6](https://github.com/ipc2026-numeric/team-6)
- 판단: dominance pruning과 heuristic portfolio를 분해하기 좋은 구현.

### 2.5 Count Downward — C

- SNP satisficing/agile winner
- 방식: Numeric Fast Downward 기반
- optimal 핵심: numeric PDB, numeric domain abstraction + CEGAR,
  canonical admissible combination
- satisficing/agile: interval-relaxed `hFF` GBFS
- source: [IPC team-7](https://github.com/ipc2026-numeric/team-7)
- 판단: 최신 abstraction heuristic 기준선.

### 2.6 PlanForge — A/C

- 방식: PDDL→SAS+ translator, preprocessor, search, heuristic을 Rust로 재구현
- 범위: full numeric PDDL2.1을 목표; IPC는 SNP configuration
- heuristic: numeric LM-cut, canonical domain abstraction, Metric-FF-style relaxed plan
- 특징: numeric value tolerance canonicalization으로 floating duplicate 오류 완화
- code: [mrlab-ai/PlanForge](https://github.com/mrlab-ai/PlanForge),
  [IPC team-8](https://github.com/ipc2026-numeric/team-8)
- 판단: NFD보다 현대적이지만 현재 experimental.

### 2.7 PATTINT — C

- 방식: PATTY 위의 cost-optimal SMT planner
- 특징: numeric task를 integer-valued form으로 변환해 integer arithmetic SMT 활용
- source: [IPC team-9](https://github.com/ipc2026-numeric/team-9)
- 판단: integer-valued capacity benchmark에서 PATTY와 직접 비교할 가치가 큼.

### 2.8 Count Downward Together — C

- SNP optimal winner
- 방식: Numeric Fast Downward sequential portfolio
- 구성: numeric PDB + domain abstraction의 canonical heuristic, numeric LM-cut,
  선택적으로 symmetry/orbit-space search
- source: [IPC team-11](https://github.com/ipc2026-numeric/team-11)
- 판단: optimal SNP에서 단일 heuristic보다 강한 portfolio 기준선.

### 2.9 Tempest Numeric — C

- 방식: Rust forward state-space planner
- 범위: IPC 제출은 SNP; 전체 Tempest는 temporal-numeric 지향
- numeric parser는 assign/increase/decrease/scale와 arbitrary arithmetic을 다루지만
  제출 heuristic/search가 보장하는 fragment는 별도로 확인해야 함
- 핵심: Metric-FF-style interval RPG, numeric supporter multiplicity,
  resource consumption, nonconstant supporting effect 고려
- source: [IPC team-12](https://github.com/ipc2026-numeric/team-12)
- 판단: resource consumption을 더 직접 다루는 modern relaxed-plan 비교군.

## 3. Temporal-numeric planner

### 3.1 Metric-FF — B

- 방식: FF의 delete relaxation을 numeric variable로 확장한 forward search
- 범위: PDDL2.1 level 2, instantaneous numeric; temporal planner는 아님
- 핵심: monotonic numeric relaxation, relaxed plan extraction, helpful actions
- source: [FF/Metric-FF homepage](https://fai.cs.uni-saarland.de/hoffmann/ff.html)
- 판단: 거의 모든 후속 numeric relaxed heuristic의 출발점.

### 3.2 LPG / LPG-td — B

- 방식: temporal action graph 위 stochastic local search
- 범위: PDDL2.1 numeric/durative; LPG-td는 PDDL2.2 timed initial literal와 derived predicate
- 특징: anytime/quality configuration, complex plan metric
- source/download: [official LPG page](https://lpg.unibs.it/lpg/)
- UP adapter: [aiplan4eu/up-lpg](https://github.com/aiplan4eu/up-lpg)
- 판단: state-space search와 다른 local-search baseline.

### 3.3 SAPA — D

- 방식: time-stamped state forward search
- 범위: durative action, continuous resource consumption, multi-objective cost/makespan
- heuristic: relaxed temporal planning graph의 cost/time propagation
- paper: [SAPA](https://arxiv.org/abs/1106.5260)
- 판단: multi-objective metric-temporal heuristic의 역사적 기준.

### 3.4 MIPS — B/D

- 방식: heuristic forward search와 symbolic/model-checking 기술을 결합한 IPC-era planner
- 범위: IPC3에서 Numeric, HardNumeric, temporal/complex track 참가
- 근거: [IPC3 result table](https://ipc02.icaps-conference.org/results.html)
- 판단: 재현보다는 역사적 비교와 benchmark provenance에 가치.

### 3.5 TLPlan / SHOP2 numeric — B/D

- 방식: hand-coded control rule(TLPlan), HTN domain method(SHOP2)
- 범위: IPC3 numeric/hard-numeric까지 다뤘지만 domain-independent baseline은 아님
- 근거: [IPC3 results](https://ipc02.icaps-conference.org/results.html)
- 판단: 사람이 준 domain control knowledge의 upper/reference baseline으로만 분류.

### 3.6 TP4 / SemSyn — D

- IPC3에서 numeric problem을 시도한 역사적 planner
- 근거: [IPC3 results](https://ipc02.icaps-conference.org/results.html)
- 판단: 실행 baseline 우선순위는 낮지만 역사 목록에서는 보존.

### 3.7 CRIKEY / CRIKEY3 — B

- 방식: forward-chaining temporal planning, temporal constraint reasoning
- 범위: discrete numeric change; CRIKEY3가 COLIN의 직접 기반
- source archive: [Planning at King's](https://sourceforge.net/projects/tsgp/files/)
- 판단: COLIN/POPF 계보 이해용.

### 3.8 COLIN — B

- 방식: forward heuristic search + LP temporal/numeric consistency
- 범위: PDDL2.1 full temporal semantics와 continuous linear numeric change
- 특징: concurrent continuous updates, duration-dependent effects를 LP에 반영
- source: [Planning at King's archive](https://sourceforge.net/projects/tsgp/files/COLIN/)
- paper: [COLIN](https://arxiv.org/abs/1401.5857)
- 판단: continuous linear numeric planning의 필수 역사 baseline.

### 3.9 POPF — A/B

- 방식: forward-chaining partial-order temporal search
- 특징: action을 earliest time에 고정하지 않고 partial-order plan과 LP schedule 유지
- dependency: COIN-OR CLP/CBC, VAL parser
- code: [fmrico/popf](https://github.com/fmrico/popf)
- archive: [Planning at King's](https://sourceforge.net/projects/tsgp/files/POPF/)
- 판단: temporal partial-order search의 실사용 baseline.

### 3.10 OPTIC — A/B

- 방식: POPF 기반 forward temporal search + LP
- 범위: continuous numeric fluents, preferences, time-dependent costs, plan metric optimization
- code: [KavrakiLab/optic](https://github.com/KavrakiLab/optic)
- original archive: [Planning at King's](https://sourceforge.net/projects/tsgp/files/OPTIC/)
- 판단: 사용자가 언급한 핵심 temporal-numeric baseline. 현대화 fork를 우선 확보.

### 3.11 LPRPG / LPRPG-P — B

- 방식: relaxed planning graph + LP/MIP resource-flow reasoning
- 범위: producer-consumer resource와 numeric goals; P variant는 preference까지 확장
- source: [Planning at King's](https://sourceforge.net/projects/tsgp/files/LPRPG/)
- 판단: capacity/resource competition 가설과 직접 연결되는 필수 heuristic/planner.

### 3.12 Temporal Fast Downward(TFD) — B

- 방식: temporal state-space heuristic search
- heuristic: context-enhanced additive heuristic의 temporal/numeric 확장
- code mirror: [neighthan/tfd](https://github.com/neighthan/tfd)
- paper: [Eyerich et al. 2009](https://ojs.aaai.org/index.php/ICAPS/article/view/13373)
- 판단: Fast Downward 계보의 temporal-numeric reference.

### 3.13 SGPlan numeric/temporal — D

- 방식: subgoal partitioning + planning/scheduling 결합
- IPC-era temporal/numeric system이나 현대적으로 유지되는 공식 source는 재확인 필요
- 판단: 논문 비교표에는 포함하되 첫 acquisition 대상에서는 제외.

### 3.14 TAMER — A(제한 라이선스)

- 방식: ANML 기반 temporal planning, heuristic search/SMT 계열
- 범위: integer/real numeric variable, durative action, ICE, timed goals/effects
- distribution: non-commercial 중심; UP adapter 제공
- official: [TAMER](https://tamer.fbk.eu/), [up-tamer](https://github.com/aiplan4eu/up-tamer)
- 판단: 안정적 temporal application platform이 필요할 때 사용.

### 3.15 NextFLAP — A/B

- 방식: forward partial-order planning + SMT numeric constraint solver/optimizer
- 범위: PDDL2.2의 광범위한 temporal/numeric feature, continuous effect 제외;
  numeric control parameter 확장
- code: [ossaver/NextFLAP](https://github.com/ossaver/NextFLAP)
- UP package: [up-nextflap](https://pypi.org/project/up-nextflap/)
- 판단: expressive temporal-numeric와 numeric action parameter 연구에 유용.

### 3.16 Aries — A

- 방식: chronicles 기반 lifted plan-space encoding + 자체 CP/lazy-clause-generation solver
- 범위: PDDL/HDDL, temporal 및 numeric state variable, plan quality optimization
- code: [plaans/aries](https://github.com/plaans/aries)
- 판단: SMT가 아닌 현대 constraint-programming baseline.

### 3.17 PATTY Temporal / PATTY ICE — C

- 방식: temporal numeric pattern을 SMT로 encoding
- 범위: PDDL2.1 level 3, 이후 intermediate conditions/effects
- paper: [Temporal Numeric Planning with Patterns](https://arxiv.org/abs/2412.09101),
  [ICE extension](https://arxiv.org/abs/2602.09798)
- code: [matteocarde/patty](https://github.com/matteocarde/patty)
- 판단: OPTIC/TamerLite와 대조되는 temporal symbolic baseline.

### 3.18 Tempest / OPTIC++ lineage — C/D

- 방식: temporal piecewise-linear numeric planning, lazy LP consistency checking
- 특징: continuous effect segment의 consistency check를 필요할 때 지연하고 LP footprint 축소
- paper: [Bajada, Fox, Long 2021](https://arxiv.org/abs/2105.10176)
- 판단: COLIN/OPTIC LP scheduling의 현대적 개선 계열. 공개 stable package 여부는 재확인 필요.

### 3.19 CP4TP / TFLAP / TemPorAl — A/B, temporal 중심

- 방식: temporal-to-classical compilation portfolio(CP4TP), forward partial-order(TFLAP) 등
- code: [aig-upf/temporal-planning](https://github.com/aig-upf/temporal-planning)
- 판단: 모든 구성 요소가 rich numeric을 지원하는 것은 아니므로 numeric benchmark에
  투입하기 전 feature matrix를 실제 parser test로 확인한다.

## 4. PDDL+ 및 hybrid planner

### 4.1 UPMurphi — B

- 방식: PDDL+를 finite/discretised Murphi model로 compile한 뒤 explicit model checking
- 범위: linear/nonlinear process, event, TIL/TIF
- heuristic: 기본 release는 blind search
- code/site: [UPMurphi](https://gdellapenna.github.io/research/upmurphi/)
- 판단: discretise-and-validate의 비휴리스틱 기준점.

### 4.2 DiNo — B

- 방식: UPMurphi 확장, discretise-and-validate + informed search
- 범위: linear/nonlinear continuous PDDL+, process/event, TIL/TIF
- heuristic: Staged Relaxed Planning Graph Plus(SRPG+), helpful time-passing
- code: [KCL-Planning/DiNo](https://github.com/KCL-Planning/DiNo)
- 판단: PDDL+ heuristic-search 필수 baseline이나 구형 flex/32-bit dependency 주의.

### 4.3 SMTPlan+ — A/B

- 방식: PDDL+를 SMT로 compile, continuous time을 symbolic하게 유지
- 범위: PDDL2.1/PDDL+, process/event, polynomial continuous change 범위
- backend: Z3
- code: [KCL-Planning/SMTPlan](https://github.com/KCL-Planning/SMTPlan)
- 판단: discretisation 없는 symbolic PDDL+ baseline.

### 4.4 TM-LPSAT — D

- 방식: PDDL+를 Boolean formula + linear arithmetic constraint로 compile,
  LPSAT/MathSAT으로 해결
- 범위: action/durative action/process/event, real/interval fluent, continuous linear change
- paper: [Shin & Davis 2005](https://doi.org/10.1016/j.artint.2005.04.001)
- 판단: 현대 SMTPlan+ 계보의 역사적 기반.

### 4.5 dReal-based nonlinear PDDL+ planner — D

- 방식: PDDL+를 nonlinear hybrid-system reachability formula로 encoding,
  delta-complete SMT(dReal) 사용
- 범위: nonlinear continuous process; durative action compile
- paper: [Gao et al. 2015](https://scungao.github.io/papers/planning.pdf)
- 판단: nonlinear symbolic solving reference. 공개 planner package는 이번 조사에서 미확인.

### 4.6 CASP PDDL+ planner — D/C

- 방식: Constraint Answer Set Programming
- 특징: discretised hybrid planning을 ASP의 Boolean reasoning과 numeric constraint로 결합
- paper: [PDDL+ Planning via CASP](https://arxiv.org/abs/1609.00030)
- 판단: SMT 이외의 declarative baseline.

### 4.7 Nyx — C/D

- 방식: 가볍고 수정 가능한 Python 기반 PDDL+ planner
- 목적: real-world customization과 PDDL+ adoption 장벽 완화
- paper: [Real-World Planning with PDDL+ and Beyond](https://arxiv.org/abs/2402.11901)
- 판단: 논문과 사용 사례는 확인했으나 공식 source repository는 이번 조사에서 확인하지 못함.

### 4.8 NEAT — D

- 방식: lifted GBFS + Hybrid Temporal Situation Calculus + 외부 nonlinear programming solver
- 특징: 사전 grounding과 time discretisation을 피하고 action time을 symbolic하게 유지
- 입력은 PDDL+에서 HTSC로 번역 후 일부 수작업 정제가 보고됨
- paper: [Heuristic Planning for Hybrid Dynamical Systems with CLP](https://ceur-ws.org/Vol-3585/paper5_IPS1.pdf)
- 판단: nonlinear/lifted 방향의 연구 prototype; 즉시 실행 baseline은 아님.

### 4.9 Kongming — D

- 방식: Graphplan + mathematical programming subsolver
- 범위: continuous process를 다룬 초기 hybrid planner
- 판단: 역사적 related work. plan graph horizon 확장성이 주요 제한.

## 5. 별도 분류해야 하는 것

- Fast Downward, LAMA, SymK 자체는 일반 배포판 기준으로 native numeric planner가 아니다.
  BitBlast 같은 compilation 뒤의 backend로는 중요하다.
- VHPOP은 temporal partial-order planner지만 numeric precondition/effect baseline으로
  간주하면 안 된다.
- 일반 MILP/SMT solver(CPLEX, Gurobi, Z3, OptiMathSAT, Yices, SCIP)는 planner가 아니라
  planner encoding의 backend다.
- CP-SAT, bin packing solver는 domain-specific oracle로 매우 유용하지만 PDDL planner는 아니다.
