# 플래너 확보와 재현 계획

이 문서는 조사 목록을 실제 실행 가능한 benchmark suite로 옮기기 위한 순서다.
아직 외부 source를 workspace에 clone하지 않았다. 각 repository의 license와 build를
확인한 뒤 `planners/external/<name>`에 commit/tag를 고정하는 것을 권장한다.

## 1. 공통 기반부터 확보

| 구성요소 | 용도 | 공식 링크 |
|---|---|---|
| Unified Planning | parser/compiler/engine adapter 공통층 | [repository](https://github.com/aiplan4eu/unified-planning) |
| VAL | sequential/temporal/numeric plan validation | [repository](https://github.com/KCL-Planning/VAL) |
| planutils | 여러 legacy planner 설치 보조 | [repository](https://github.com/AI-Planning/planutils) |
| IPC 2023 domains | SNP/LNP 회귀 suite | [repository](https://github.com/ipc2023-numeric/benchmarks) |
| IPC 2026 domains | 최신 SNP/LNP 회귀 suite | [repository](https://github.com/ipc2026-numeric/benchmarks) |

공통 wrapper는 `run <domain> <problem> <plan-output>` 인터페이스로 통일하고,
planner별 원본 stdout/stderr와 plan을 보존한다.

## 8. 공정 비교를 위한 configuration 원칙

- 동일 problem file을 모든 planner가 실제로 같은 semantics로 읽는지 확인한다.
- Unsupported feature를 compiler가 조용히 제거하지 않게 한다.
- Grounding/preprocessing을 wall-clock에 포함한 결과와 search-only 결과를 둘 다 둔다.
- External solver startup과 license checkout도 end-to-end time에 포함한다.
- Stochastic planner는 여러 seed를 실행한다.
- Anytime planner는 first-plan time과 best-plan-at-cutoff를 분리한다.
- Optimal planner와 satisficing planner는 coverage table을 분리한다.
- Search planner와 symbolic planner는 plan horizon 영향까지 설명한다.
- All returned plans는 동일 VAL version 또는 독립 replay로 검증한다.
- Float tolerance와 strict inequality 처리 차이를 기록한다.

## 9. 실제 첫 baseline set 권고

첫 capacity/grouping 논문 실험에는 아래 7개면 방법론 축을 넓게 덮는다.

1. Metric-FF — 원형 numeric RPG
2. ENHSP — 현대 subgoaling/MRP search
3. Panino — novelty-enhanced satisficing search
4. Numeric Fast Downward/NLM-CutPlan — LM-cut/OC optimal search
5. Count Downward — abstraction heuristic
6. PATTY — SMT symbolic pattern planning
7. LPRPG — producer-consumer LP guidance

추가로 OMTPlan, BitBlast+LAMA, exact bin-packing oracle를 붙이면 search, SMT/OMT,
LP, abstraction, compilation, domain-specific optimization을 모두 비교할 수 있다.
