# 우수 플래너·휴리스틱 조합과 세부 방법론

- 실험 원본: `results/raw/changmin-heuristics-all-20260912-160327-347232/results.csv`
- 실험 조건: 6개 도메인 × `p000`~`p004`, timeout 300초, CPU 2개, 메모리 12 GiB
- 작성 목적: 성능이 좋았던 구성을 재사용 가능한 baseline으로 고정하고, 결과가 나온 이유를
  탐색과 numeric relaxation 수준에서 해석한다.

## 1. 먼저 읽어야 할 결론

이 실험에는 모든 기준에서 하나로 우월한 configuration이 없다.

- **가장 넓고 빠른 satisficing baseline**: Metric-FF `numeric-hff`
- **가장 강한 완주형 탐색 baseline**: Panino `hadd-novelty`
- **coverage와 구조적 guidance의 균형**: Count Downward `irhff`
- **coverage와 plan objective의 균형**: NFD `irhadd`
- **좋은 목적함수 값을 자주 찾은 subgoaling 계열**: ENHSP `hadd`, `hradd`
- **Assembly 특화 relaxed-plan baseline**: ENHSP `hmrp`
- **느리지만 좋은 목적함수 값을 찾은 A* baseline**: PlanForge `ff`
- **해를 찾으면 최적성 기준을 제공하는 baseline**: NFD/PlanForge `lmcutnumeric`

여기서 configuration은 단순한 휴리스틱 이름이 아니다.

> **configuration = planner의 상태 표현 + 휴리스틱 + search engine + cost 설정 + preferred-action 정책**

같은 `hFF`나 `LM-cut` 이름을 사용해도 번역기, numeric relaxation, open list와
cost interpretation이 다르면 서로 다른 방법이다.

## 2. 선정 기준과 실험 성능

다음 세 기준 중 하나를 만족한 구성을 보존했다.

1. **범용형**: 30문제 중 25문제 이상에서 VAL-valid plan 생성
2. **특화형**: 어려운 `p003`·`p004`에서 특정 도메인의 최저 observed objective 생성
3. **기준선**: admissible heuristic과 A*로 최적 비용의 기준 제공

### Metric-FF 해석에서 반드시 지킬 점

실험 명령은 다음 형태였다.

```bash
plannerctl run metric-ff-cross-v1 -o DOMAIN -f PROBLEM
```

Metric-FF는 `-O`를 줘야 PDDL optimization expression을 사용하고, 기본값은 plan
length이다. 이번 실험에는 `-O`가 없었다. 따라서 CSV의 `objective_value`는 VAL이
완성된 plan에 대해 계산한 **사후 측정값**이다. Metric-FF가 그 값을 직접 최소화했다고
해석하면 안 된다.

이 차이는 결과를 잘 설명한다.

- Logistics와 Watering에서는 action 수가 짧아도 이동시간·물 운반시간이 클 수 있어 빠르지만
  objective가 나빴다.
- Barman에서는 불필요한 조작을 줄이는 것과 실행시간 감소가 비교적 강하게 정렬되어,
  plan-length 지향 탐색도 좋은 objective를 만들었다.

## 4. 공통 수학적 틀

### 4.1 원래 numeric planning 문제

상태를 다음과 같이 둔다.

\[
s=(P,\mathbf{x})
\]

- \(P\): 현재 참인 명제 집합
- \(\mathbf{x}\in\mathbb{R}^m\): fuel, load, volume, total-time 같은 numeric fluent 벡터

행동 \(a\)는 명제 전제조건과 선형 numeric 조건을 함께 가진다.

\[
pre(a)=P_a^+\cup P_a^-\cup
\{\boldsymbol{\alpha}_j^T\mathbf{x}\ \bowtie_j\ \beta_j\}
\]

효과는 add/delete와 numeric update로 구성된다.

\[
eff(a)=add(a),del(a),\qquad
\mathbf{x}'=F_a(\mathbf{x})
\]

실제 탐색은 delete, 자원 소비, 객체 점유, 상호배타성 때문에 행동 순서에 민감하다.
반면 아래의 relaxation들은 이 정보 일부를 버려 계산 가능한 근사 문제를 만든다.

### 4.2 명제 delete relaxation

고전적인 delete relaxation에서는

\[
P' = P \cup add(a)
\]

로 두고 `del(a)`를 무시한다. 한 번 얻은 사실은 영원히 남는다. 따라서 실제 문제의
다음 구조가 약해지거나 사라진다.

- 손이 비어 있어야 다시 집을 수 있음
- 트럭이나 카트가 한 장소에만 존재함
- shaker가 깨끗한 상태와 사용 중인 상태를 동시에 가질 수 없음
- 선행 조립이 끝나야 후속 조립을 할 수 있음

### 4.3 additive heuristic의 기본식

명제 \(p\)의 relaxed cost를 \(C(p)\)라 하자.

\[
C(p)=
\begin{cases}
0 & p\in s\\
\min_{a:p\in add(a)} C(a) & \text{otherwise}
\end{cases}
\]

행동 cost는

\[
C(a)=c(a)+\sum_{q\in pre(a)}C(q)
\]

이고, conjunction은 합, disjunction은 최소로 결합한다.

\[
h_{add}(s)=\sum_{g\in G}C(g)
\]

이 방식은 서로 다른 goal이 같은 supporter를 공유해도 그 비용을 여러 번 더할 수 있다.
그래서 admissible하지 않지만, 여러 subgoal을 동시에 처리해야 한다는 압력을 강하게 준다.

### 4.4 numeric threshold를 넣은 additive propagation

numeric 조건을 하나의 연속적인 값으로만 보지 않고, 달성해야 할 threshold subgoal로 본다.
예를 들어

\[
q:\boldsymbol{\alpha}^{T}\mathbf{x}\ge \beta
\]

에 대해 현재 부족량을

\[
d_q(s)=\max(0,\beta-\boldsymbol{\alpha}^{T}\mathbf{x}(s))
\]

로 둔다. 행동 \(a\) 한 번이 이 조건의 좌변을 상수 \(\Delta_{a,q}>0\)만큼 개선한다면
필요 반복 횟수의 단순 근사는

\[
k_{a,q}(s)=\left\lceil\frac{d_q(s)}{\Delta_{a,q}}\right\rceil
\]

이고 supporter 후보 비용은 다음처럼 쓸 수 있다.

\[
C_q(a)=C(pre(a))+k_{a,q}(s)c(a)
\]

그 결과 numeric 조건 비용은

\[
C(q)=\min_{a:\Delta_{a,q}>0}C_q(a)
\]

로 전파할 수 있다. 실제 ENHSP와 interval/repetition 계열은 여러 fluent의 reachable
interval, 비교식의 방향, achiever 순서와 의존성을 더 다루지만 핵심 질문은 같다.

> 어떤 행동을 몇 번 반복해야 numeric inequality가 참이 되는가?

이 근사에서 문제가 되는 정보는 다음과 같다.

- fuel을 늘리는 주유와 budget 감소가 결합된 trade-off
- 한 fluent를 개선하면 다른 fluent가 악화되는 coupled effect
- 동일 action의 효과량이 현재 numeric state에 의존하는 effect
- 여러 numeric condition이 같은 유한 자원을 경쟁하는 관계
- threshold를 넘긴 뒤 다시 내려가면 행동이 불가능해지는 비단조성

## 5. 핵심 휴리스틱 계열

### 5.1 `hadd`: subgoal 비용을 더한다

`hadd`는 relaxed problem에서 각 조건의 최소 달성비용을 전파하고 goal 비용을 합한다.

장점:

- 많은 package, book, plant, part처럼 병렬 subgoal 수가 늘어날수록 남은 일의 양을 잘 드러낸다.
- 단순 goal count보다 행동 전제조건의 깊이와 numeric threshold 도달 비용을 반영한다.
- 계산이 relaxed-plan extraction이나 abstraction보다 비교적 싸다.

한계:

- 공유 supporter를 중복 계산한다.
- delete를 무시하여 차량 위치, 손 점유, 도구 상태 같은 충돌을 보지 못한다.
- 독립으로 계산한 numeric subgoal들이 실제로는 같은 budget/capacity를 소비할 수 있다.

### 5.2 `hFF`: 하나의 relaxed plan을 추출한다

`hFF`는 relaxed planning graph에서 goal부터 역추적해 supporter 행동 집합 \(\pi^+\)를
선택한다.

\[
h_{FF}(s)=\sum_{a\in\pi^+}c(a)
\]

`hadd`와 달리 같은 supporter가 여러 goal을 달성하면 relaxed plan에서 한 번만 셀 수 있다.
따라서 action sharing을 어느 정도 잡지만, 어떤 achiever를 역추적에서 골랐는지에 민감하다.
numeric 버전은 threshold를 달성하는 effect와 필요한 반복 수를 relaxed plan에 포함한다.

### 5.3 interval/repetition relaxation

interval relaxation은 각 numeric variable의 단일 예상값 대신 도달 가능한 구간을 유지한다.

\[
I_i=[L_i,U_i]
\]

행동 효과를 적용할수록 이 구간을 넓히며, 비교식이 구간 안의 어떤 값으로 만족 가능하면
relaxed reachable로 처리한다. repetition 확장은 행동을 여러 번 적용했을 때 threshold에
도달하는 횟수를 추정한다.

핵심 이점은 `fuel >= distance`, `water >= demand`처럼 단일 실행으로 만족되지 않는 조건도
표현한다는 것이다. 핵심 손실은 각 fluent의 구간을 따로 유지할 때 변수 간 correlation이
사라진다는 점이다. 예를 들어 `[fuel high]`와 `[budget high]`가 각각 reachable여도 두 값이
동시에 가능한 실제 상태가 없을 수 있다.

### 5.4 numeric LM-cut

LM-cut은 relaxed problem에서 반드시 지나야 하는 행동 집합, 즉 landmark cut을 반복해 찾는다.
한 iteration에서 cut \(L_i\)의 최소 잔여 cost를

\[
\delta_i=\min_{a\in L_i}c_i(a)
\]

로 구하고, 해당 cut 행동들의 잔여 cost에서 \(\delta_i\)를 빼며 누적한다.

\[
h_{LMcut}(s)=\sum_i\delta_i
\]

각 cut은 모든 relaxed solution이 최소 하나를 선택해야 하는 행동 집합이다. 비용을 cut들에
나누어 더하므로 같은 action cost를 함부로 중복 계산하지 않으며, 지원 fragment에서는
admissible하다. A*와 결합하면 완료된 문제에 대해 최적 plan cost를 보장하는 기준선이 된다.

대신 매 상태에서 여러 번의 relaxed reachability와 cut 추출을 반복한다. numeric bound와
반복량 계산까지 들어가면 한 노드의 평가비용이 크다. `lmcutnumeric`이 19/30만 풀었지만
성공한 19문제에서 모두 observed best와 일치한 이유가 여기에 있다.

### 5.5 partitioned numeric novelty

novelty search는 목표까지의 거리만 묻지 않고, 지금까지 보지 못한 feature 또는 feature pair를
가진 상태를 우선한다. Panino의 실험 configuration은 상태를 정수화한 `hadd` 값으로 partition한다.

\[
partition(s)=\lfloor h_{add}(s)\rfloor
\]

각 partition 안에서:

- novelty 1: 처음 본 단일 Boolean/numeric feature
- novelty 2: 처음 본 feature pair
- novelty 3: 둘 다 새롭지 않음

을 구하고 다음 사전식 순서로 open list에서 꺼낸다.

\[
(novelty(s),h_{add}(s),-g(s))
\]

즉 새 구조를 먼저 탐색하고, 같은 novelty에서는 goal에 가까운 상태, 그래도 같으면 더 깊이
진행한 상태를 우선한다. numeric feature는 비교식까지의 거리 개선을 기록하며 Boolean–numeric
pair도 포함한다. pair table이 너무 커지면 구현은 메모리 보호를 위해 novelty 1만 사용한다.

## 6. configuration별 실제 방법론

### 6.1 Metric-FF · `numeric-hff`

#### 처리 순서

1. PDDL numeric 표현을 monotonic relaxation에 맞게 정규화한다.
2. relaxed planning graph를 전개한다. 명제 delete는 무시한다.
3. numeric 조건을 만족시키는 방향으로 effect를 누적해 비교식의 도달 가능성을 판정한다.
4. goal layer에서 역추적하여 relaxed plan을 하나 선택하고 `hFF`를 계산한다.
5. EHC가 더 작은 `hFF`를 갖는 상태를 찾으며 내려간다.
6. plateau나 local minimum에서 EHC가 실패하면 best-first search로 전환한다.
7. 첫 plan을 반환한다.

#### 왜 빨랐는가

- 모든 문제에서 첫 유효 plan을 얻는 데 필요한 guidance가 충분했다.
- EHC와 helpful actions가 분기 수를 공격적으로 줄였다.
- admissible bound나 최적성 증명을 하지 않았다.
- 이번 실행은 `-O`가 없어 plan length를 기본 비용으로 사용했다.

#### 무엇을 놓치는가

- budget과 fuel, 위치와 적재 같은 상호 의존
- highway를 선택해 얻는 실행시간 절감과 toll 지출의 장기 trade-off
- 당장 relaxed plan을 짧게 만드는 행동이 실제 objective를 크게 만드는 경우

#### 실험에서의 역할

30/30을 매우 빠르게 풀어 **parser/solvability 및 빠른 satisficing upper bound**로 가장 좋다.
그러나 Logistics p003에서 objective 483 대 observed best 144, p004에서 774 대 196이었다.
objective-quality 대표로 사용해서는 안 된다.

### 6.2 Panino LNP Agile · `hadd-novelty`

#### 정확한 구성

Panino의 `novbfs_hg` search는 전달된 일반 heuristic을 내부에서 unit-cost additive `H1`으로
교체한다. helpful-action pruning은 사용하지 않는다. 각 successor에 대해:

1. `hadd`를 계산한다.
2. `floor(hadd)` partition을 선택한다.
3. parent와 비교해 새 Boolean 사실, numeric comparison distance 개선, feature pair를 찾는다.
4. novelty 1/2/3을 부여한다.
5. `(novelty, hadd, -g)`로 frontier에 넣는다.

#### 왜 완주했는가

relaxed heuristic이 같은 값만 내는 plateau에서도 novelty가 아직 보지 못한 조합을 향해 탐색을
퍼뜨린다. delete relaxation의 잘못된 gradient 하나에만 매달리지 않으므로 30/30을 완주했다.

#### 왜 objective는 나빴는가

주 우선순위는 objective가 아니라 novelty와 unit-cost `hadd`다. 높은 `g` 우선은 세 번째
tie-break일 뿐이다. 새 feature를 얻기 위한 우회 행동도 장려될 수 있다. 따라서 coverage는
최고지만 objective gap 중앙값은 35.0%였다.

#### 연구상 가치

Panino는 **잘못된 heuristic gradient를 탐색 다양성으로 보완할 수 있는가**를 묻는 baseline이다.
새로 설계할 numeric constraint 단계에서 relaxation의 정보 손실이 커져도 coverage가 유지되는지
보기 좋다.

### 6.3 Count Downward Agile · `irhff`

#### 정확한 alias

실험의 IPC agile alias는 다음과 동등하다.

```text
hff = irhff(cost_type=one)
lazy_greedy(hff, preferred=hff, cost_type=one)
```

#### 처리 순서

1. numeric fluent별 reachable interval을 확장한다.
2. numeric comparison을 만족하는 목표값과 필요한 action repetition을 추정한다.
3. goal에서 achiever를 역추적해 반복 relaxed plan을 만든다.
4. relaxed plan cost를 `irhff`로 사용한다.
5. 현재 상태에서 적용 가능하고 relaxed plan에 포함된 행동을 preferred operator로 표시한다.
6. lazy greedy search가 작은 `irhff`를 우선하고 preferred successor를 앞세운다.

#### 강점

단순 numeric RPG보다 반복 횟수를 명시적으로 다루고, A*보다 빠른 lazy greedy search와
preferred operator가 결합된다. Books p003/p004에서 각각 objective 305/420으로 observed best를
찾은 것은 symbolic sequence와 action count가 execution time에 잘 정렬된 결과로 해석할 수 있다.

#### 한계

`cost_type=one`이므로 PDDL의 execution-time metric을 직접 최적화하지 않는다. 또한 interval은
개별 변수의 범위를 결합할 때 correlation을 잃는다. Barman 대형 문제에서는 조작 순서와
공유 도구 상태가 커져 coverage가 3/5로 낮아졌다.

### 6.4 Numeric Fast Downward · `irhadd`

#### 처리 순서

1. 실제 상태에서 proposition과 numeric variable의 interval seed를 만든다.
2. 반복 relaxation으로 각 proposition과 numeric threshold의 relaxed 도달 cost를 전파한다.
3. 각 goal proposition의 cost를 합한다.

\[
h_{irhadd}(s)=\sum_{g\in G}C_{repeat}(g)
\]

4. 실험에서는 `astar(irhadd())`로 `f=g+h`가 작은 상태를 확장한다.
5. `irhadd`는 non-admissible이고 inconsistent이므로 첫 goal의 최적성은 보장되지 않는다.

#### 왜 plan quality가 좋았는가

- A*의 `g`가 지금까지 지불한 실제 action cost를 반영한다.
- 반복 relaxation이 threshold까지 필요한 행동량을 반영한다.
- additive aggregation이 남은 여러 배송·급수·조립 subgoal을 강하게 평가한다.

coverage 27/30, objective gap 중앙값 7.2%로 이 실험에서 coverage와 quality의 균형이 가장
좋은 축에 속한다. Barman p004에서도 250.079초를 사용해 objective 204를 찾아 observed best를
기록했다.

#### 한계

goal cost 합산은 공유 행동을 중복 계산하고, non-admissible A*는 많은 상태를 보존한다.
그래서 quality는 좋아도 timeout과 memory-limit에 취약하다.

### 6.5 Numeric Fast Downward · `irhff`

`irhff`는 같은 interval/repetition exploration 뒤에 하나의 relaxed plan을 역추적한다.
선택된 operator별 반복 횟수 \(r_a\)를 구해

\[
h_{irhff}(s)=\sum_{a\in\pi^+}r_a c(a)
\]

로 평가한다. 구현은 relaxed plan의 처음 층에서 실제 적용 가능한 행동을 preferred operator로
생성할 수 있다. 다만 이번 명령은 `astar(irhff())`였고 별도의 preferred open list를 지정하지
않았으므로, 이 실험에서는 그 기능이 탐색 순서를 주도하지 않았다.

`irhadd`보다 공유 supporter 중복은 줄지만 greedy achiever extraction의 선택에 민감하다.
22/30만 풀었으나 성공한 22문제 중 17문제가 observed best와 같았고 Assembly p004에서
objective 279를 0.213초에 찾았다. 따라서 `irhadd`와 함께 **합산 대 relaxed-plan extraction**의
직접 대조군으로 가치가 있다.

### 6.6 ENHSP · `hadd`

#### 처리 순서

ENHSP의 `H1(additive=true, extractRelaxedPlan=false)`는 compact grounded problem을 만들고,
현재 참인 terminal condition의 cost를 0으로 초기화한다. 전제조건 conjunction의 비용을
더하고, 각 action이 만드는 proposition과 numeric comparison의 cost를 반복 갱신한다.

실험의 `WAStar`는 weight 1이므로 open-list 값은

\[
f(s)=g(s)+h_{add}(s)
\]

이다. `hadd`가 admissible하지 않으므로 이름이 A* 형태여도 최적성 보장은 없다.

#### numeric 처리의 중요한 경계

상수형 `increase/decrease`는 comparison 방향에 대한 numeric contribution을 계산할 수 있다.
반면 효과량이 상태값에 복잡하게 의존해 안전하게 평가할 수 없으면 구현은
`UNKNOWNEFFECT`로 표시해 hard numeric condition처럼 다룬다. 로그의
`Numeric Error for Complex Condition Activated`는 이 방어 경로가 활성화되었다는 뜻이다.

#### 결과 해석

25/30, gap 중앙값 5.8%로 좋은 plan을 자주 찾았지만, relaxation 계산과 A* frontier가 커지면
대형 Logistics/Watering/Barman에서 느려졌다. **objective-aware지만 완주성보다 plan quality에
기운 satisficing baseline**으로 사용한다.

### 6.7 ENHSP · `hradd`

`hradd`는 `hadd`와 같은 additive propagation을 사용하되 action precondition과 goal의 numeric
조건에 redundant constraints를 추가한다. 코드의 `brute` 변환은 정규화된 conjunction에서
이미 내포되는 비교식을 명시적으로 생성한다.

예를 들어 강한 조건이

\[
x\ge 10
\]

이라면 문제 구조에 따라 `x >= 5` 같은 중간·내포 constraint가 명시적 terminal로 추가될 수
있다. 이 feature는 heuristic이 threshold 진행도를 더 일찍 관찰하도록 만든다.

장점은 sparse한 numeric signal을 촘촘하게 만드는 것이다. 단점은 terminal condition과
propagation 관계가 증가하며, redundant constraint가 실제 변수 correlation을 복원하는 것은
아니라는 점이다.

Watering p004에서 `hradd`는 0.871초에 objective 339로 observed best를 찾았다. 그러나 전체 gap
중앙값은 `hadd`보다 나빴다. 따라서 항상 상위인 개선판이 아니라 **threshold 가시성에 대한
구조적 변형**이다.

### 6.8 ENHSP · `hmrp`

`hmrp`는 additive H1 propagation 뒤 `extractRelaxedPlan=true`와 multi-repetition relaxed-plan
estimate를 사용한다. 단순히 각 goal cost를 합하지 않고 achiever를 역추적하면서 numeric
condition 달성에 필요한 최대 반복량과 supporter action을 relaxed plan으로 모은다.

효과:

- 여러 goal이 같은 조립/이동 supporter를 공유하면 중복을 줄인다.
- numeric threshold를 한 번의 action 존재가 아니라 반복량으로 환산한다.
- 구현상 relaxed plan의 첫 행동을 helpful action으로 만들 수 있다. 다만 이번 실험에서는
  `-ha true`를 주지 않았으므로 pruning에는 사용하지 않았다.

Assembly p003/p004에서 각각 objective 176/233으로 observed best를 기록했고, 두 problem 모두
약 10초 이내였다. Assembly는 조립 단계와 부품 상태의 supporter chain이 뚜렷해 relaxed-plan
extraction이 실제 plan 구조와 잘 맞는다. 반대로 위치·budget·도구 점유가 복잡하게 충돌하는
도메인에서는 relaxed plan이 낙관적으로 합쳐져 coverage가 21/30에 그쳤다.

### 6.9 PlanForge · `ff`

PlanForge의 `ff()`는 Metric-FF식 monotonic numeric relaxation을 구현한다.

1. 각 numeric variable에 `(min_reachable, max_reachable)` envelope를 둔다.
2. effect가 envelope를 넓히면 갱신한다.
3. `>=`, `<=`, `=`, `!=` comparison axiom이 envelope에서 가능해지는 층을 기록한다.
4. goal에서 greedy cheapest supporter를 역추적한다.
5. 선택된 relaxed operator의 cost 합을 `hFF`로 반환한다.
6. 실험에서는 GBFS가 아니라 `astar(ff())`를 사용한다.

conditional effect는 synthetic pseudo-operator로 확장하고 parent action cost가 중복되지 않도록
처리한다. 부호 반전 때문에 sound envelope를 만들기 어려운 multiply/divide assignment는
조용히 약화하지 않고 unsupported error로 종료한다.

PlanForge의 A*는 PDDL metric에서 번역된 action cost를 `g`에 반영하지만 `ff`가
non-admissible이므로 최적성은 보장하지 않는다. 그럼에도 Logistics p003에서 56.311초에
objective 144로 observed best를 찾았고, Watering p003에서도 184로 best와 동률이었다.
coverage 22/30과 긴 timeout 누적은 좋은 quality의 대가다.

### 6.10 NFD/PlanForge · `lmcutnumeric`

두 configuration 모두 `astar(lmcutnumeric())`이고 이번 30문제에서 동일하게 19문제를 풀어
19개 모두 observed best와 일치했다. PlanForge 구현은 NFD 계열의 numeric LM-cut 동작과 옵션을
재현하는 독립 Rust 경로이므로, 결과 재현성을 확인하는 쌍으로 보존한다.

NFD plugin이 명시하는 성질:

- action costs 지원
- admissible: yes
- consistent: no
- preferred operators: no
- conditional effects와 axioms: 지원하지 않음

inconsistent heuristic이므로 A* 구현은 더 좋은 `g`가 발견된 상태를 적절히 다시 열 수 있어야
최적성 주장이 유지된다. 지원 fragment에서 search가 정상 완료되어 goal을 반환하면 그 cost는
최적값이다. timeout/memory-limit이면 **실패가 아니라 미증명**이며, incumbent가 없다면 coverage에는
잡히지 않는다.

이 baseline의 역할은 많이 푸는 것이 아니라 다음 두 가지다.

1. 다른 satisficing configuration의 objective gap을 계산할 최적 cost 제공
2. numeric interaction이 cut 계산과 A* 상태 수를 얼마나 폭발시키는지 측정

## 7. 도메인별로 어떤 구조가 맞았는가

| 도메인 | 잘 맞은 구성 | 구조적 이유 | 주의할 실패 |
|---|---|---|---|
| Logistics | PlanForge `ff`, NFD `irhadd`, ENHSP `hadd/hradd` | 실제 action cost와 threshold 반복량이 route 선택에 필요 | plan length만 보면 highway/toll/fuel trade-off를 놓침 |
| Books | Count Downward `irhff`, Metric-FF | symbolic sequence와 action 수가 실행시간에 비교적 정렬 | shelf numeric 상태와 cart 공유 충돌이 커지면 relaxation 낙관화 |
| Watering | ENHSP `hadd/hradd/hmrp`, PlanForge `ff` | 물 수요 threshold와 이동 cost를 함께 봐야 함 | Metric-FF의 unit/length 지향 plan은 objective가 크게 악화 |
| Barman | Metric-FF, NFD `irhadd` | 짧은 조작 sequence가 시간과 강하게 상관; 대형은 반복량·cost 필요 | shaker/hand 상태의 delete와 순서 의존이 커지면 급격히 어려움 |
| Assembly | ENHSP `hmrp`, NFD `irhff` | supporter chain과 반복 relaxed-plan 구조가 실제 precedence와 유사 | 단순 합산은 공유 supporter를 중복 평가 |

## 8. 논문에서의 권장 baseline 묶음

모든 45개 configuration을 본문에서 같은 무게로 다루지 않는다. 아래 여섯 역할을 고정하면
결과 해석이 선명하다.

| 실험 질문 | 주 baseline | 대조 baseline |
|---|---|---|
| 아주 빠르게 아무 유효 plan이나 찾는가 | Metric-FF `numeric-hff` | Panino `hadd-novelty` |
| relaxation gradient가 틀려도 탐색을 계속하는가 | Panino `hadd-novelty` | ENHSP `hadd` |
| numeric 반복량이 도움이 되는가 | NFD `irhadd` | ENHSP `hadd` |
| relaxed-plan extraction이 합산보다 좋은가 | NFD `irhff`, ENHSP `hmrp` | NFD `irhadd`, ENHSP `hadd` |
| redundant threshold가 도움이 되는가 | ENHSP `hradd` | ENHSP `hadd` |
| 찾은 objective가 최적인가 | NFD/PlanForge `lmcutnumeric` | 모든 satisficing 구성 |

핵심 종속변수도 분리해야 한다.

- **coverage**: valid plan 수
- **planning efficiency**: wall time, expanded nodes, peak RSS
- **plan quality**: objective value와 proven optimum 대비 gap
- **scaling failure mode**: timeout, memory-limit, unsupported, parser failure

특히 plan을 찾는 속도와 plan의 실행시간은 다른 변수다. `planning wall time`과 domain의
`objective_value`를 절대로 하나의 “time” 열로 합치지 않는다.

## 9. 동일 configuration 재실행

아래에서 `DOMAIN`과 `PROBLEM`만 실제 파일로 바꾸면 된다.

```bash
# ENHSP additive variants
./planners/plannerctl run enhsp -o DOMAIN -f PROBLEM -h hadd  -s WAStar -ties arbitrary
./planners/plannerctl run enhsp -o DOMAIN -f PROBLEM -h hradd -s WAStar -ties arbitrary
./planners/plannerctl run enhsp -o DOMAIN -f PROBLEM -h hmrp  -s WAStar -ties arbitrary

# Metric-FF: 원 실험 재현. -O가 없다는 점이 중요하다.
./planners/plannerctl run metric-ff-cross-v1 -o DOMAIN -f PROBLEM

# IPC 2026 고정 alias
./planners/plannerctl run count-downward-agile DOMAIN PROBLEM
./planners/plannerctl run panino-lnp-agile DOMAIN PROBLEM

# Numeric Fast Downward
./planners/plannerctl run numeric-fast-downward-local DOMAIN PROBLEM --search 'astar(irhadd())'
./planners/plannerctl run numeric-fast-downward-local DOMAIN PROBLEM --search 'astar(irhff())'
./planners/plannerctl run numeric-fast-downward-local DOMAIN PROBLEM --search 'astar(lmcutnumeric())'

# PlanForge
./planners/plannerctl run planforge-ipc2026 --search 'astar(ff())' DOMAIN PROBLEM
./planners/plannerctl run planforge-ipc2026 --search 'astar(lmcutnumeric())' DOMAIN PROBLEM
```

Metric-FF의 PDDL metric 최적화 효과를 새로 비교하려면 별도 실험군으로 `-O`를 추가해야 한다.
기존 결과와 같은 configuration인 것처럼 섞지 않는다.

```bash
./planners/plannerctl run metric-ff-cross-v1 -o DOMAIN -f PROBLEM -O
```
