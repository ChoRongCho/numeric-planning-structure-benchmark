# 독립 실행 환경 안내

모든 runtime은 `planners/runtime/<id>`에 분리되며 시스템 경로에 planner를
설치하지 않는다. 공통 진입점은 `planners/plannerctl`이다.

## 상태 확인

```bash
planners/plannerctl list
planners/plannerctl status patty
planners/plannerctl sources
planners/plannerctl source numeric-fast-downward
```

상태의 의미:

| 상태 | 의미 |
|---|---|
| `verified-plan` | 실제 PDDL 문제를 읽고 plan을 생성함 |
| `verified-compiler` | 실제 numeric PDDL을 변환함 |
| `verified-cli` | 배포물이 현재 JVM/OS에서 시작하고 CLI를 표시함 |
| `host-blocked` | 배포된 32-bit binary가 현재 sandbox syscall 정책에서 차단됨 |
| `build-blocked` | 소스와 실행 script는 staging됐지만 legacy compiler/ABI 때문에 build 실패 |
| `runtime-blocked` | 일부 native component는 build됐지만 필수 runtime이 불완전함 |

## batch 실행 가능한 43개 구성

정확한 현재 목록은 `scripts/run/benchmarkctl planners`의 `batch=true` 행이다.
여기에는 POPF, OPTIC, Numeric Fast Downward, Count Downward, PlanForge,
Ferroplan, PATTINT, Panino, TemPEST, TamerLite IPC 2026 및 기존 구성들이
포함된다. 각 ID는 YAML에서 독립적으로 선택할 수 있으며 `planners: ["*"]`는
이 43개만 선택한다. 이 중 `popf-static-v2`는 사용자 Ubuntu host에서 실행되며,
Codex sandbox의 32-bit seccomp에서는 실행할 수 없다. 생성 plan은 다른 구성과
동일하게 case별 VAL 검증을 거친다.

아래에서 `ROOT`는 이 repository의 절대 경로다.

```bash
ROOT="$PWD"
NUM_DOMAIN="$ROOT/planners/external/ipc2023-numeric-dataset/counters/domain.pddl"
NUM_PROBLEM="$ROOT/planners/external/ipc2023-numeric-dataset/counters/instances/pfile1.pddl"
METRIC_DOMAIN="$ROOT/planners/external/ipc2023-numeric-dataset/zenotravel/domain.pddl"
METRIC_PROBLEM="$ROOT/planners/external/ipc2023-numeric-dataset/zenotravel/instances/pfile1.pddl"
TEMP_DOMAIN="$ROOT/domains/smoke/temporal/domain.pddl"
TEMP_PROBLEM="$ROOT/domains/smoke/temporal/problem.pddl"
```

### Metric-FF current / 2.0

```bash
planners/plannerctl run metric-ff -o "$METRIC_DOMAIN" -f "$METRIC_PROBLEM"
planners/plannerctl run metric-ff-2.0 -o "$METRIC_DOMAIN" -f "$METRIC_PROBLEM"
```

### ENHSP

```bash
planners/plannerctl run enhsp -o "$NUM_DOMAIN" -f "$NUM_PROBLEM"
```

### TamerLite / NextFLAP

```bash
planners/plannerctl run tamerlite "$NUM_DOMAIN" "$NUM_PROBLEM"
planners/plannerctl run nextflap "$NUM_DOMAIN" "$NUM_PROBLEM"
```

TamerLite와 NextFLAP은 서로 다른 local `site-packages`를 사용한다. TamerLite는
Rust 가속 없이 pure-Python core로 검증됐다.

### OMTPlan

```bash
OMT_ROOT="$ROOT/planners/external/omtplan/pddl_examples/benchmarks_IJCAI20/simple/counters"
planners/plannerctl run omtplan -omt -parallel \
  -domain "$OMT_ROOT/domain.pddl" "$OMT_ROOT/instances/instance_2.pddl"
```

### PATTY / SpringRoll

```bash
planners/plannerctl run patty -o "$NUM_DOMAIN" -f "$NUM_PROBLEM"
planners/plannerctl run springroll -o "$NUM_DOMAIN" -f "$NUM_PROBLEM"
```

PATTY의 ANTLR runtime은 생성 코드에 맞춰 4.12.0으로 고정했다. SpringRoll은
자체 JAR들과 OMTPlan runtime의 local Z3 executable을 사용한다.

### LPG-td

```bash
LPG_ROOT="$ROOT/planners/runtime/lpg-td/LPG-td-1.4/FlawTIL-UMTS"
planners/plannerctl run lpg-td -o "$LPG_ROOT/domain.pddl" \
  -f "$LPG_ROOT/p10.pddl" -n 1
```

### CRIKEY2

```bash
planners/plannerctl run crikey2 "$TEMP_DOMAIN" "$TEMP_PROBLEM"
```

## 변환이 검증된 compiler

```bash
mkdir -p planners/runtime/bitblast/output
planners/plannerctl run bitblast "$NUM_DOMAIN" "$NUM_PROBLEM" \
  "$ROOT/planners/runtime/bitblast/output" --bits 8 --base
```

## CLI가 검증된 실행기

```bash
planners/plannerctl run aries --help
planners/plannerctl run fape --help
planners/plannerctl run fape-1.0 --help
planners/plannerctl run sapa
```

- Aries release는 PDDL 직접 입력이 아니라 Unified Planning protobuf server/client다.
- FAPE는 PDDL이 아니라 ANML 입력 planner다.
- SAPA JAR는 시작되지만 현재 smoke fixture와 구형 parser가 호환되지 않아 plan
  생성 성공으로 분류하지 않았다.

## staging됐지만 현재 host 또는 검증 단계에서 차단된 항목

| ID | 차단 원인 |
|---|---|
| `cpt`, `crikey`, `tsgp` | 32-bit historical executable의 syscall이 현재 sandbox seccomp에서 차단 |
| `mips-xxl-seq`, `mips-xxl-netben` | 현대 Bison이 생성한 parser와 2008 C source 비호환 |
| `gamer-netben` | 32-bit include/glibc toolchain 비호환 |
| `hspsp-netben` | 32-bit linker runtime 부족 |
| SGPlan6 세 snapshot | 현대 GCC common-symbol/parser/static-link 문제 |
| `tfd-ipc2008` | C++ search/preprocess는 build되지만 bundled Python 2.5의 `select` module build 실패 |
| `lnm-plan-ipc2023` | build와 CLI 실행 성공, `19_COUNTERS/p001`에서 invalid 0-step plan을 반환하여 batch 제외 |
| `numeric-fast-downward`, LNM 공식 구성 | 동일 입력 반복 실행 중 valid plan과 invalid 0-step plan이 모두 관측되어 batch 제외 |
| Count Downward optimal 2개 구성 | tiny smoke case에서도 120초 내 plan을 내지 않아 batch 제외 |

이 항목들은 원본과 staging tree가 모두 있으므로 Ubuntu 8.04/10.04 계열 container
image 또는 보존 VM을 붙이면 같은 `plannerctl` entry를 유지한 채 runtime만 교체할 수
있다.
