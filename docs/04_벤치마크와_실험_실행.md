# 벤치마크와 실험 실행

## 논문에서 벤치마크의 역할

IPC benchmark와 `changmin_benchmark`는 planner coverage를 비교하고 실패가
집중되는 domain을 찾는 **탐색용 corpus**다. 여기에서 발견한 timeout 패턴 자체를
곧바로 구조적 원인이라고 주장하지 않는다. 원인 후보가 생기면 size, tightness,
coupling을 독립 조절한 최소 problem family와 대조군으로 다시 검증한다.

분석 순서는 [02 문제 발견 프레임워크](02_문제_발견_프레임워크.md)를 따른다.

일반 실험의 사용자 인터페이스는 `scripts/run/experiment.yaml`이다. YAML에서
planner, domain별 problem, timeout, 병렬 실행 수와 저장 위치를 정한 뒤 고정된
run script를 실행한다.

```bash
cd scripts/run
./run
```

`benchmarkctl`은 YAML runner가 사용하는 내부 실행 엔진의 고급 CLI다. 원본
PDDL은 변경하지 않으며 모든 planner 출력은 `results/raw/<run-id>/` 아래에
보존한다. YAML 전체 필드 설명은 `scripts/run/README.md`를 참고한다.

## Catalog 확인

```bash
scripts/run/generate_benchmark_manifest.py
scripts/run/benchmarkctl list
scripts/run/benchmarkctl planners
scripts/run/benchmarkctl validate-pddl
```

- `benchmarks/manifest.yaml`: domain, instance glob/count, SHA-256, PDDL feature
- `planners/capabilities.json`: batch adapter와 지원 기능
- `validate-pddl`: 모든 domain/problem 조합을 VAL parser로 검사

`manifest.yaml`은 외부 Python package 없이 읽을 수 있도록 JSON 문법으로 기록한
YAML 1.2 파일이다. PDDL을 변경하면 manifest를 다시 생성해야 한다.

## 실행

한 planner와 benchmark 전체:

```bash
scripts/run/benchmarkctl run \
  --planner enhsp \
  --benchmark 33_SAILING \
  --timeout 300
```

인스턴스 하나만 실행:

```bash
scripts/run/benchmarkctl run \
  --planner metric-ff \
  --benchmark 37_ZENOTRAVEL \
  --instance p001 \
  --timeout 60
```

여러 planner/domain의 첫 문제만 smoke test:

```bash
scripts/run/benchmarkctl run-all \
  --planners metric-ff enhsp tamerlite patty \
  --benchmarks 06_TSP_NUMERIC 19_COUNTERS 33_SAILING \
  --smoke --jobs 4 --timeout 60
```

전체 526개 문제를 실행하려면 `--smoke`를 생략한다. 기능표상 지원하지 않는
조합은 `unsupported`로 기록된다. 조사 목적으로 강제 실행할 때만
`--force-unsupported`를 사용한다.

## 결과 구조

```text
results/raw/<run-id>/
  manifest.json
  results.csv
  cases/<planner>/<benchmark>/<instance>/
    command.json
    planner.log
    resource.txt
    result.json
    plan.val
    validation.log
    work/
      domain.pddl
      problem.pddl
```

`results.csv`의 상태는 `solved`, `unsolved`, `timeout`, `crash`, `parse-error`,
`unsupported`, `unknown` 중 하나다. 추출 가능한 plan은 VAL로 검증하며
`validation` 열에 `valid`, `invalid`, `not-extracted`, `not-run` 등을 기록한다.

각 case는 입력 PDDL 사본에서 실행되므로 LPG-td나 SpringRoll처럼 입력 파일 옆에
plan을 생성하는 planner도 원본 `benchmarks/`를 오염시키지 않는다.

## 재현성 정보

run의 `manifest.json`에는 다음이 기록된다.

- UTC 시작/종료 시각
- timeout과 병렬 job 수
- planner와 benchmark 선택
- planner runtime 상태
- benchmark manifest SHA-256
- 결과 상태별 개수

각 case에는 실제 argv, 원본 stdout/stderr, wall time, 최대 RSS가 별도로 남는다.
