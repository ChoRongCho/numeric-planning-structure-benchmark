# 실행한 10개 numeric planner의 방법론과 heuristic

작성일: 2026-09-11  
대상 실행: `results/raw/selected-10-all-domains-p001-20260911-144247-062274`

이 문서는 완료된 10-planner 실행을 해석하기 위한 방법론 기록이다. 이후 기본 비교군에
추가된 `optic-cplex`, `popf-static-v2`, `numeric-fast-downward-local`은 해당 결과에
포함되지 않는다. 현재 13개를 하나의 동일 실험 결과처럼 합쳐 해석하지 않는다.

## 결론

**10개 planner가 모두 같은 delete-relaxation heuristic을 사용한 것은 아니다.**

- 7개는 이번 실행에서 delete relaxation을 직접 사용하는 relaxed-plan 또는
  numeric subgoaling heuristic을 사용했다: ENHSP, Metric-FF, Count Downward,
  Panino, TamerLite, Tempest Numeric, OPTIC.
- PlanForge는 numeric delete relaxation에서 도출한 `hmax` 구조와 landmark cut을
  누적하는 **numeric LM-cut**을 사용했다. 넓은 의미에서는 relaxation 기반이지만,
  `hFF`처럼 relaxed plan 하나를 추출하는 방식은 아니다.
- PATTY와 PATTINT는 상태마다 `h(s)`를 계산해 open list를 정렬하는 planner가 아니다.
  action pattern과 plan bound를 SMT로 encoding하여 푼다. ARPG가 pattern 생성 또는
  action ordering에 쓰일 수는 있지만, 이것을 `hFF`나 `hadd`와 같은 search
  heuristic이라고 부르면 안 된다.

따라서 넓게 세면 **8/10이 delete-relaxation 기반 heuristic**, 엄격하게
"relaxed plan/subgoaling heuristic을 직접 평가한다"고 세면 **7/10**, 나머지
**2/10은 heuristic state-space search가 아닌 SMT 계열**이다.

`delete relaxation`도 하나의 알고리즘 이름이 아니다. Boolean delete effect와
numeric harmful interaction을 완화한 동일한 발상 위에서도 `hFF`, `hadd`,
interval-relaxed `hFF`, numeric LM-cut, temporal RPG는 서로 다른 정보를 계산한다.

## 1. 10개 planner의 방법론

| 실험 ID | planner 방법론 | 이번 탐색/해법 | delete relaxation과의 관계 |
|---|---|---|---|
| `enhsp` | grounded forward state-space search. Numeric 조건을 subgoal로 regression하고 supporter 비용을 전파 | 기본 `WAStar` + 기본 `hadd` | 직접 사용: numeric delete-relaxation subgoaling |
| `metric-ff-cross-v1` | Metric-FF의 monotonic numeric relaxation, relaxed planning graph와 relaxed-plan extraction | EHC를 먼저 시도하고 실패하면 `1*g + 5*h` best-first | 직접 사용: numeric `hFF` |
| `count-downward-agile` | Fast Downward 계열의 SAS progression search. Numeric reachable 값을 interval/repetition relaxation으로 전파 | `lazy_greedy(hff, preferred=hff)` | 직접 사용: interval-relaxed `hFF` (`irhff`) |
| `planforge-ipc2026` | Rust PDDL→SAS+ pipeline과 explicit-state search. Numeric landmark cut의 비용을 반복 누적 | `A*` + `lmcutnumeric()` | 간접/상위 구조: numeric delete relaxation 위의 LM-cut |
| `patty-ipc2026-agile-1` | Symbolic Pattern Planning. causal action pattern의 subsequence/repetition과 numeric feasibility를 SMT로 해결 | `jair` pattern search + Z3 | 상태 heuristic 없음. ARPG/causal 분석은 pattern 생성용 |
| `panino-lnp-agile` | JPDDL+ progression search에 numeric novelty를 결합. `hadd` 값으로 partition한 novelty-guided best-first | `novbfs_hg`; novelty 후 higher-`g` tie-breaking | base heuristic이 직접 numeric delete-relaxation `hadd` 사용 |
| `tamerlite-ipc2026-agile-1` | UP 기반 temporal/numeric forward heuristic search | `GBFS` + `hadd`, weight 1 | 직접 사용: numeric delete-relaxation `hadd` |
| `pattint-bitwuzla` | bounded symbolic numeric planning. action/pattern 선택과 numeric transition을 bit-vector SMT로 encoding | bound 1부터 증가, Bitwuzla로 solve | 상태 heuristic 없음. ARPG action order는 encoding pattern용 |
| `tempest-numeric-ipc2026` | Rust forward search. 실행 횟수 bound/range를 포함한 Metric-FF식 numeric RPG에서 relaxed plan 추출 | 기본 EHC + helpful actions; 실패 시 A* fallback | 직접 사용: `hFF`와 RPG-derived landmarks |
| `optic` | forward-chaining partial-order temporal/numeric search. STN/LP로 schedule과 numeric feasibility를 검사 | 기본 EHC, 실패 시 weight 5의 WA*; 이번 binary는 COIN-OR CLP backend | 직접 사용: temporal/numeric RPG relaxed-plan heuristic |

### 방법론별로 무엇이 다른가

- `hFF`: relaxed goal을 만족하는 **한 relaxed plan을 추출**하고 그 action 수/비용을
  사용한다. Metric-FF, Count Downward의 `irhff`, Tempest, OPTIC이 같은 큰 계열이다.
- `hadd`: relaxed subgoal별 achiever 비용을 더한다. ENHSP, Panino, TamerLite가
  이번 실행에서 사용했다. goal 간 supporter 공유를 중복 계산할 수 있다.
- numeric LM-cut: relaxed `hmax` plateau에서 반드시 지나야 하는 cut을 찾고 action
  cost를 차감하며 cut cost를 누적한다. PlanForge의 이번 구성이다.
- Symbolic Pattern Planning / bounded SMT: search state별 scalar `h(s)` 대신, bound
  전체의 action과 numeric state 관계를 논리식으로 만들고 SMT solver가 모델을 찾는다.
  PATTY와 PATTINT가 여기에 해당한다.
- novelty는 relaxation이 아니다. Panino에서는 `hadd`가 partition을 만들고 novelty가
  그 안의 탐색 순서를 추가로 정한다.

## 2. 각 planner에서 지원하는 heuristic 모음

여기서 "지원"은 이번에 고정한 binary/source revision에서 이름이 CLI 또는 heuristic
registry에 실제로 존재한다는 뜻이다. 모든 heuristic이 모든 PDDL feature에서 동작하거나,
현재 설치된 optional solver dependency까지 갖췄다는 뜻은 아니다.

### 2.1 ENHSP

실행 JAR의 `-h` 도움말에 노출된 목록:

- `aibr`: Additive Interval-Based Relaxation
- `hadd`: additive numeric subgoaling
- `hradd`: `hadd` + redundant constraints
- `hmax`: numeric `hmax`
- `hrmax`: `hmax` + redundant constraints
- `hmrp`: Multi-Repetition Relaxed Plan extraction
- `blcost`: goal state 0, non-goal state 1
- `blind`: 모든 state에 0
- `ngc`: Numeric Goal Counting

검색기는 `gbfs`, `lazygbfs`, `WAStar`, `wa_star_4`를 선택할 수 있다. 검색기 이름은
heuristic 이름과 별개다.

### 2.2 Metric-FF cross v1

- 선택 가능한 별도 heuristic family는 없다.
- 고정된 core heuristic은 monotonic numeric relaxation의 `hFF`이다.
- `-E`로 EHC를 끄고, `-g`/`-h`로 fallback best-first의 `g`/`h` weight를 바꿀 수
  있지만 heuristic 자체를 교체하는 옵션은 아니다.

### 2.3 Count Downward

현재 source에 등록된 numeric heuristic을 계열로 묶으면 다음과 같다.

- interval/AIBR relaxation: `aibr`, `iihmax`, `iihadd`, `iihff`, `irhmax`,
  `irhadd`, `irhff`
- numeric subgoaling/generalization: `hrmax`, `hgen`
- landmarks/cuts: `lmcutnumeric`; `lm_scala` landmark factory
- numeric pattern database: `numeric_pdb`, `numeric_cpdbs`, `numeric_ipdb`
- domain abstraction: `domain_abstraction`, `max_domain_abstractions` 및 canonical
  combination
- uninformed/classical registry: `blind`, `goalcount`, `add`, `ff`, classical
  `hmax` 등

마지막 classical heuristic들은 purely propositional task 또는 지원되는 compiled
fragment에 한정될 수 있다. 이름이 등록되어 있다는 사실과 arbitrary numeric task에서
의미 있게 동작한다는 사실은 구분해야 한다.

### 2.4 PlanForge IPC 2026

`HeuristicSpec`에 등록된 목록:

- `blind`
- `ff`
- `lmcutnumeric`
- `greedy_numeric_pdb`
- `canonical_numeric_pdb`
- `domain_abstraction`
- `canonical_domain_abstractions`
- `multi_domain_abstractions`
- `scp_online`: online saturated cost partitioning
- `fillscp`/`fill_scp`: fill-based saturated cost partitioning 구성 이름

검색기는 `astar`, `gbfs`, 두 heuristic을 지연 평가하는 `astar_fs`를 지원한다.

### 2.5 PATTY IPC 2026

전통적인 state heuristic 목록은 **없다**. 대신 다음 symbolic configuration을
지원한다.

- pattern 생성: `arpg`, `enhanced`, `random`
- 공개 CLI search: `static`, `step`, `astar`, `jair`
- SMT backend: `yices`, `z3`
- numeric-effect encoding: `binary`, `non-linear`
- JAIR ordering/scoring: search strategy `C/B/R/G`, goal function `n/g/a`,
  pattern-`h` `c/i/s`, pattern-`g` `r/p/o/e`

여기서 `pattern-h`라는 옵션명은 PATTY 내부의 pattern 평가/선택 설정이다. 일반적인
planner state의 `h(s)`와 동일시하지 않는다.

### 2.6 Panino IPC 2026

내장 JPDDL+ heuristic registry:

- goal/distance: `gc`, `ngc`, `agnosticngc`, `mgc`
- subgoaling: `hadd`, `haddb`, `hmax`, `hradd`, `hrmax`, `hrmaxb`
- resolution: `h1res`, `h1res2`, `h1res3`, `h1res4`
- relaxed-plan/repetition: `hmrp`, `hmrpb`, `hmrp_fix`, `hmrp_easy_fix`,
  `hmrp_fix_tran`
- interval/generalized: `aibr`, `hgen`
- landmark: `hlm-count`, `hlm-lp`, `hlm-lp-gurobi`
- uninformed: `blind`, `01blind`

`hlm-lp` 계열은 CPLEX/Gurobi 같은 optional dependency가 필요할 수 있다. Panino의
novelty search configurations는 `novbfs_lg`, `novbfs_hg`이며, novelty 자체는 위
base heuristic registry와 다른 search guidance 층이다.

### 2.7 TamerLite IPC 2026

현재 engine registry:

- `hff`, `hadd`, `hmax`
- `hmax_explicit`
- `hff_no_numbers`, `hadd_no_numbers`, `hmax_no_numbers`
- `blind`
- Python callable을 받는 `custom`

앞의 `hff`/`hadd`/`hmax`는 구현 주석이 명시하는 delete-relaxation heuristic이다.
`*_no_numbers`는 numeric reasoning을 비활성화한 variant이다.

### 2.8 PATTINT

전통적인 state heuristic 목록은 **없다**. 조절 가능한 symbolic 구성은 다음과 같다.

- pattern: `arpg`, `random`
- encoding: `non-linear`, `binary`
- solver backend: source의 SMT backends; 이번 실행 binary 경로는 Bitwuzla
- bound/deepening, `binary-actions`, `roll-bound`, effect axioms

ARPG가 action pattern/order를 제공하지만 각 concrete state를 `h(s)`로 평가하지는
않는다.

### 2.9 Tempest Numeric IPC 2026

- 이 제출본이 노출하는 heuristic family는 Metric-FF식 numeric RPG `hFF` 하나다.
- relaxed plan에서 helpful actions와 action multiplicity를 추출한다.
- 초기 RPG에서 얻은 propositional disjunctive landmark의 pending count를 A* 경로의
  보조 정보로 결합한다.
- EHC, A*, GBFS fallback, macro successor, eager/lazy evaluation 옵션은 search 또는
  successor-generation 설정이지 별도 heuristic family가 아니다.

### 2.10 OPTIC

- CLI로 교체 가능한 heuristic family는 없다.
- temporal/numeric relaxed planning graph의 relaxed-plan estimate가 core heuristic이다.
- helpful-action pruning, EHC 사용 여부, best-first/WA*와 tie-breaking은 바꿀 수 있다.
- LP/STN consistency 검사는 실제 partial plan의 시간·수치 feasibility를 확인하는
  machinery이며, 별도의 `hadd`/LM-cut 선택지가 아니다.
- OPTIC에는 LP solver가 필요하지만 **CPLEX만 가능한 것은 아니다**. 현재 repository는
  CLP 또는 CPLEX build를 지원하며, 이번 실험은 `optic-clp`를 실행했다. 이 binary는
  workspace의 `libOsiClp`, `libClp`, `libOsi`, `libCoinUtils`에 link되어 있고 CPLEX에는
  link되어 있지 않다. 일부 abstraction 기능에는 CPLEX가 필요할 수 있다.
- 이 실행 이후 제공된 Ubuntu용 static `optic-cplex` binary도 별도 planner ID
  `optic-cplex`로 등록하고 `03_BLOCKSWORLD/p001`에서 plan 생성과 VAL 검증을 완료했다.
  이는 위의 10-planner 실행에는 포함되지 않았으며, 이후 CLP/CPLEX backend 비교에
  사용할 수 있다. 두 binary의 core heuristic family는 모두 OPTIC의 temporal/numeric RPG다.

### 이번 실험에서 실제 비교된 heuristic 구성의 수

planner ID는 10개지만 heuristic baseline 10개를 비교한 것은 아니다.

- `hadd` 계열: ENHSP, Panino, TamerLite — 3개
- `hFF`/RPG 계열: Metric-FF, Count Downward, Tempest, OPTIC — 4개
- numeric LM-cut: PlanForge — 1개
- scalar state heuristic 없음: PATTY, PATTINT — 2개

같은 이름도 구현이 같지 않다. 예를 들어 Count Downward의 `irhff`는 interval과
action repetition을 사용하고, Tempest의 `hFF`는 per-action execution bound와 numeric
range를 사용하며, OPTIC은 temporal layers와 LP-backed feasibility machinery를 함께
사용한다. 따라서 결과를 분석할 때는 단순히 `delete relaxation vs non-delete
relaxation` 두 그룹으로만 집계하면 구현 차이가 사라진다.

## 5. 해석할 때 지켜야 할 경계

- 이 문서는 **방금 실행한 configuration**을 설명한다. planner가 이론상 지원하는
  모든 heuristic을 이번 실험에서 시험했다는 뜻이 아니다.
- 특히 ENHSP는 command가 heuristic을 명시하지 않았기 때문에 실행 JAR의 default인
  `hadd`를 사용했다. 다음 실행부터 exact configuration을 보존하려면 `-h hadd -s
  WAStar`처럼 명시하는 편이 재현성이 높다.
- PATTY/PATTINT의 성능 차이는 delete relaxation의 정보 손실만으로 설명할 수 없다.
  pattern 품질, bound 증가, SMT formula 크기와 solver behavior가 함께 작용한다.
- OPTIC은 sequential 문제에도 실행됐지만 본래 temporal/numeric planner다. LP와
  partial-order 관리 비용이 다른 sequential planner와의 runtime 차이에 포함된다.

## 6. 원 실행 이후 추가된 local artifact

다음 항목은 이 문서가 분석한 10-planner 실행에는 포함되지 않았다.

- `numeric-fast-downward-local`: 별도 제공된 modified Numeric Fast Downward source와
  기존 `release64` build를 사용한다. 기본 adapter 구성은
  `astar(lmcutnumeric())`이다. `03_BLOCKSWORLD/p001`을 풀어 VAL 검증했고,
  기존 NFD 구성에서 비결정적 문제가 관측됐던 `19_COUNTERS/p001`도 독립 작업
  디렉터리에서 3회 연속 동일한 12-step plan을 생성하여 VAL 검증했다.
- `popf`: maintained 64-bit build이며 이미 batch/VAL 검증된 POPF 구성이다.
- `popf-static-v2`: 추가 제공된 POPF Release 2의 32-bit static binary다. 사용자
  Ubuntu host에서 실행이 확인되어 batch에 등록했다. Codex sandbox에서는 32-bit
  syscall seccomp로 `SIGSYS`가 발생하지만, 사용자 host에서 실행한 batch의 생성
  plan은 공통 runner가 VAL로 검사한다. 두 POPF ID는 동일한 방법의 서로 다른
  build/release 비교군이지 새로운 heuristic family가 아니다.
