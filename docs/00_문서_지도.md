설명할 수 있는 **numeric planning의 구조적 문제를 발견하고, 그 원인을 통제 실험으로
확인하는 프로젝트**다.

## 논문 중심 작업 순서

```text
관찰된 실패
  → 실패 단계 분리
  → relaxation에서 사라진 정보 후보 식별
  → 독립 변수를 조절하는 최소 문제 family 설계
  → heuristic 값·순위·plateau·expansion 측정
  → 여러 planner/heuristic에서 반복되는지 확인
  → 반례와 대안 설명으로 원인 가설 반증
  → 그 뒤에만 해결 방법 정의
```

현재 단계는 `문제 발견과 원인 검증`이다. learned guidance, SLM/LLM 또는 새로운
heuristic은 문제가 재현되고 누락 정보가 특정된 다음 단계다.

## 문서 번호 규칙

- 루트 문서는 논문의 논리 순서에 따라 `00_`부터 번호를 붙인다.
- 하위 폴더 문서는 폴더 안에서 다시 `00_`, `01_` 순서로 번호를 붙인다.
- 파일명은 한글로 쓰되 PDDL, numeric planning, heuristic 같은 고유 기술 용어는
  본문에서 원어를 병기한다.
- 하나의 활성 연구 질문은 [01 연구 문제 정의](01_연구_문제_정의.md)에만 둔다.
- 관찰, 해석, 가설, 결론을 문장에서 구분한다. 실패했다는 사실만으로 원인을
  delete relaxation이라고 단정하지 않는다.
